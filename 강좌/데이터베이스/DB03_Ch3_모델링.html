1. 데이터 모델링 (원본 p.2-8)

가. 데이터 모델링의 개요

데이터 모델링은 현실세계의 업무를 개념세계(추상화된 개념적 데이터 모델링)를 거쳐 컴퓨터 저장 데이터베이스로 표현하기 위한 논리적 데이터 모델링, 물리적 데이터 모델링의 과정을 거친다.

나. 정보요구사항 수집·분석 4단계

단계내용
정보 요구 사항 수집사용자의 정보 요구 사항을 수집하는 단계로, 사용자 인터뷰·설문지·워크숍·현행 시스템 분석 등을 통해 수집
정보 요구 사항 분석 및 정의수집된 정보 요구 사항을 정리하고 방법론에서 제시하는 다양한 기법으로 분석해 정의
정보 요구 사항 상세화확정된 정보 요구 사항의 개별 사항에 대해 세밀하게 분석하고 기록
정보 요구 사항 검증사용자의 정보 요구 사항이 비즈니스·조직·애플리케이션 관점과 상관분석을 통해 누락 없이 반영되었는지 검증

다. 논리 데이터 모델링 절차

라. 물리 데이터 모델링 절차와 검증

단계내용
물리 요소 조사 및 분석시스템 구축 관련 명명 규칙 파악, 하드웨어 자원 및 운영체제·DBMS 버전 파악, DBMS 파라미터 정보 및 DB 운영 관리 요소 파악

💡 Tip · 개념적 설계 단계 vs 논리적 설계 단계개념적 설계 단계는 집단화(Aggregation)·일반화(Generalization) 등 추상화 기법으로 개념적 스키마를 유도하고, 개체 간 연관성(관계성)을 식별하며, 하향식(Top-down)으로 부문별 뷰를 통합해 나가는 단계다. 반면 트랜잭션의 전체적 골격 개발과 인터페이스 정의, 트랜잭션별 데이터 접근 방법의 절차적 명세는 논리적 설계 단계(트랜잭션 인터페이스 설계)에 해당한다는 점이 자주 출제되는 함정이다.

다. 확장 E-R 모델 — 일반화/특수화와 집단화

확장 E-R 모델(EER 모델)은 기본 E-R 모델에 유용한 개념을 추가한 모델이다. 일반화(Generalization)와 특수화(Specialization)는 서로 역(逆)의 관계에 있으며 IS-A 관계·상속 개념이 적용된다. 일반화는 다수의 하위 레벨 엔티티 타입(Sub-Type)을 하나의 상위 레벨 엔티티 타입(Super-Type)으로 통합하는 것이고, 특수화는 반대로 하나의 Super-Type을 다수의 Sub-Type으로 분리하는 것이다(예: 학생 → 남학생/여학생).

집단화(Aggregation)는 여러 엔티티의 집합으로 새로운 엔티티를 정의하는 것으로, 부분과 전체 사이에 특정 개념이 적용되지 않는(즉, IS-A가 아닌 PART-OF 관계의) 구조다.

라. 세분화(Specialization)의 분리 제약조건·완전 제약조건

구분상세설명
분리 제약조건disjoint하나의 개체는 세분화의 어느 한 서브클래스의 멤버만 될 수 있다는 의미. 멤버십 프레디킷으로 사용한 애트리뷰트가 단일 값일 때는 분할 제약조건이 적용됨
overlap둘 중 어느 하나로 분리하지 못하고, 둘 다 어디에도 속할 수 있음
완전 제약조건total수퍼 클래스에 있는 모든 개체는 반드시 세분화된 서브 클래스의 한 멤버가 되어야 함을 명세
partial하나의 선으로 연결된 부분 세분화로, 수퍼 클래스의 개체는 서브 클래스에 속하지 않아도 됨(예: 학생이 대학원생·학부생 서브 클래스에 속하지 않을 수 있음)
💡 Tip · E-R 다이어그램 → 관계형 스키마 매핑 규칙일반 엔터티는 하나의 테이블로 변환되고, 1:N 관계는 'N'쪽(다(多) 쪽) 테이블의 외래키 속성으로 변환되며(반대로 '1'쪽에 속성으로 변환된다는 설명은 오답), M:N 관계는 별도의 연결(WORKS_ON류) 테이블로 변환되어 양쪽 기본키를 합성한 기본키를 갖는다. 서브타입은 수퍼타입의 키를 외래키로 사용하며, 약한 엔티티(Weak Entity)는 소유(Owner) 엔티티의 기본키와 자신의 부분키(Partial Key)를 함께 기본키로 구성해 하나의 스키마로 변환한다. 관계 타입 자체도 애트리뷰트(관계 타입의 키 등)를 가질 수 있다는 점도 함께 기억해 둔다.

3. 관계형 모델 (원본 p.35-55)

가. E-R 모델·관계형 모델·관계형 DB 용어 대응

E-R(관계-개체) 모델관계형 모델관계 DB
실체유형(Entity Type)릴레이션(Relation)테이블(Table)
실체(Entity)튜플(Tuple)로우(Row)
속성(Attribute)애트리뷰트(Attribute)컬럼(Column)

릴레이션에 포함된 애트리뷰트의 수를 차수(Degree)라 하며, 튜플의 수를 카디널리티(Cardinality)라 한다. "튜플의 수를 차수라 한다"는 설명은 차수와 카디널리티를 뒤바꾼 전형적인 오답 패턴이다.

나. 관계형 모델의 제약조건

제약조건설명
영역 제약조건각 속성 A의 값이 반드시 A의 영역 dom(A)에 속하는 원자값이어야 함
키 제약조건어떠한 두 튜플도 릴레이션의 모든 속성에 대해 같은 속성값의 조합을 가질 수 없음
개체 무결성 제약조건어떠한 기본키 값도 널(Null) 값이 될 수 없음
참조 무결성 제약조건한 릴레이션의 튜플이 다른 릴레이션의 튜플을 참조하려면 반드시 참조되는 튜플이 그 릴레이션 내에 존재해야 함

다. 키의 종류

키설명
수퍼키(Super Key)테이블 내의 레코드를 유일하게 식별해 낼 수 있는 속성 또는 속성 집합(유일성만 만족)
후보키(Candidate Key)최소성을 갖는 수퍼키로, 어떤 한 속성이라도 제거하면 수퍼키 성질을 상실
기본키(Primary Key)후보키 중 설계자가 선택한 대표성을 가진 키
외래키(Foreign Key)테이블 B의 기본키를 참조하는 테이블 A의 속성 — 한 테이블에 관계 맺은 테이블 수만큼 여러 개 존재 가능하며, 비식별 관계인 경우 Null 값도 허용될 수 있음

널(Null) 값은 '알 수 없는 값', '적용할 수 없는 값(비과세 대상자의 세금납부 항목 등)', '아직 할당되지 않은 값(비공개 휴대전화번호 등)'을 표현할 때 사용하는 것이지, 실제로 값이 확정된 0(예: 성장률이 멈춘 국가의 경제성장률 0%)을 표현하는 데는 사용하지 않는다는 점이 자주 출제된다.

라. 팬 트랩(Fan Trap)과 캐즘 트랩(Chasm Trap)

연결 함정(Connection Trap)은 E-R 모델링 과정에서 실제로 가지고 있던 정보를 잃어버리는 현상으로, 3항 관계를 2항 관계로 잘못 분리하거나 관계성 경로에 필수 개체가 누락될 때 발생한다.

구분발생 원인
팬 트랩(Fan Trap)한 개체 집합이 둘 이상의 1:N 관계성 집합을 가질 때, 특정 인스턴스가 어느 쪽에 속하는지 알 수 없게 되는 문제
캐즘 트랩(Chasm Trap)일부 엔티티 간 관계성이 존재하지 않는 경우가 발생하여 정보가 누락되는 문제

마. 3항 관계의 정규화 — 이항 관계로의 분리

기존 엔티티와 1:M 관계가 되도록 새로운 엔티티를 추가해 3항 관계를 M:N 관계 2개로 모델링하면, 정규화의 어려움(3항 관계 자체는 정규화가 까다로움)을 예방할 수 있다. 이 개선안은 기존 3항 관계를 그대로 유지한 채 정규화하는 것보다, 처음부터 1:M 관계가 되도록 새 엔티티를 추가하는 예방적 접근이 핵심이다.

4. 관계 연산 (원본 p.58-74)

가. 일반 집합 연산자

연산자기호설명
합집합(Union)∪합병 가능한 두 릴레이션 중 하나 이상에 속하는 튜플로 구성된 릴레이션을 만드는 이항 연산
교집합(Intersect)∩합병 가능한 두 릴레이션에 모두 속하는 튜플로 구성된 릴레이션을 만드는 이항 연산
차집합(Difference)−하나의 릴레이션에는 있지만 다른 릴레이션에는 없는 튜플로 구성된 릴레이션을 만드는 이항 연산
카티션 프로덕트(Cartesian Product)×두 릴레이션의 튜플로 구성 가능한 모든 조합의 튜플 집합으로 구성된 릴레이션을 만드는 이항 연산

나. 순수 관계 연산자

연산자기호설명
셀렉트(Select)σ릴레이션에서 조건에 맞는 특정 튜플을 분리하는 단항 연산(수평적 부분 집합)
프로젝트(Project)π릴레이션에서 특정 속성을 선택하여 분리하는 단항 연산(수직적 부분 집합)
조인(Join)⋈둘 이상의 릴레이션에서 조인 조건에 맞는 튜플을 조합해 새 릴레이션을 생성 — 세타조인(=,<,≤,>,≥,≠ 등 일반 조건), 동등조인(동등(=) 조건만 사용, 공통 속성이 중복 표시), 자연조인(동등 조건만 사용하되 공통 속성을 중복 없이 한 번만 표시)
디비전(Division)÷릴레이션 R, S가 있을 때, S의 모든 튜플이 대응하는 R의 튜플을 분리해 프로젝션하는 연산

다. 확장 관계 연산자

연산자기호설명
세미 조인(Semi Join)⋉ / ⋊조인 속성으로 연산자 뒤 릴레이션을 프로젝트한 결과를 연산자 앞 릴레이션에 자연 조인시키는 연산. 두 릴레이션을 자연 조인한 결과를 앞 릴레이션 속성으로 프로젝트하는 것과 동일
외부 조인(Outer Join)+한 릴레이션의 튜플에 대응 튜플이 상대 릴레이션에 없어도 제외하지 않고 Null 튜플로 채워 결과에 포함시키는 연산. 두 조인 릴레이션의 모든 튜플이 결과에 포함됨
외부 합집합(Outer Union)∪+완전하게 합병 가능하지 않은 두 릴레이션의 차수를 확장시켜 합집합을 만드는 연산

복합 연산(기본 연산의 조합으로 대체 가능한 연산)인 디비전(Division)은 R(Z, Y) ÷ S(Y) = R[Z] − ((R[Z] × S) − R)[Z]로 대체할 수 있으며, 이 식에는 프로젝션·카티션 프로덕트·차집합 3가지 기본 연산만 사용되고 셀렉션(Selection)은 사용되지 않는다는 점이 출제 포인트다.

💡 Tip · 조인 종류별 카디널리티 계산속성 B를 조인 속성으로 왼쪽 R, 오른쪽 S를 자연 조인(natural join)하면 양쪽에 공통으로 대응되는 튜플만 남아 카디널리티가 가장 작고, 왼쪽 외부 조인(left outer join)은 R의 모든 튜플을 보존하며 대응이 없는 자리는 Null로 채워 자연 조인보다 카디널리티가 크거나 같고, 전체 외부 조인(full outer join)은 R·S 양쪽의 모든 튜플을 보존해 일반적으로 가장 큰 카디널리티를 갖는다는 순서(자연조인 ≤ 편측 외부조인 ≤ 전체 외부조인)를 기억해 둔다.

5. 정규화 (원본 p.75-98)

가. 정규화의 정의와 원칙

정규화(Normalization)는 논리적 데이터 모델을 일관성 있고 중복을 제거해 안정성을 갖는 바람직한 자료구조로 만들어 이상 현상을 제거하는 무손실 분해 과정이다.

원칙내용
정보의 무손실분해된 릴레이션이 표현하는 정보는 분해되기 전의 정보를 모두 포함해야 하며, 더 바람직한 구조여야 함
데이터 중복성 감소중복으로 인한 이상현상(Anomaly)의 제거
분리의 원칙하나의 독립된 관계성은 하나의 독립된 릴레이션으로 분리하여 표현

나. 이상 현상(Anomaly)의 종류

구분종류내용
데이터 종속삽입 이상(Insertion Anomaly)특정 튜플을 삽입하려 할 때 원하지 않는 불필요한 데이터도 함께 삽입해야 하는 현상
삭제 이상(Deletion Anomaly)특정 튜플을 삭제할 경우 유지되어야 하는 정보까지 함께 삭제되는 연쇄 삭제 현상
데이터 중복갱신 이상(Update Anomaly)특정 속성값 갱신 시 중복 저장된 값 중 일부만 갱신되어 발생하는 데이터 불일치 현상

다. 함수 종속성의 종류와 대응 정규형

종류설명관련 정규화
완전함수종속성X'⊂X이고 X'→Y를 만족하는 애트리뷰트 X'이 존재하지 않음-
부분함수종속성X'⊂X이고 X'→Y를 만족하는 애트리뷰트 X'이 존재함2NF(위배 시 2NF 미달)
이행함수종속성X→Y이고 Y→Z일 때 X→Z가 성립3NF(위배 시 3NF 미달)
결정자함수종속성함수적으로 종속되는 결정자가 후보키가 아닌 경우(즉 X→Y일 때 X가 후보키가 아님)BCNF(위배 시 BCNF 미달)

라. 함수 종속성 추론 규칙(암스트롱의 공리)

구분추론 규칙내용
기본 규칙(건전성)재귀성 규칙(Subset Property)Y⊆X이면 X→Y
부가성 규칙(Augmentation)X→Y이면 XZ→YZ
이행성 규칙(Transitivity)X→Y이고 Y→Z이면 X→Z
부가 규칙(완전성)분해 규칙(Decomposition)X→YZ이면 X→Y이고 X→Z
합집합 규칙(Union)X→Y이고 X→Z이면 X→YZ
의사이행성 규칙(Pseudotransitivity)X→Y이고 WY→Z이면 WX→Z
💡 Tip · 정규형 판단 3단계 흐름① 부분함수종속(기본키 일부 속성이 다른 속성을 결정)이 있으면 2NF 미달, ② 이행함수종속(비키 속성이 다른 비키 속성을 결정)이 있으면 3NF 미달, ③ 결정자가 후보키가 아닌 함수종속이 있으면 BCNF 미달이라는 순서로 점검한다. 릴레이션을 BCNF로 분해할 때는 결정자가 되는 모든 속성이 후보키가 되도록 릴레이션을 나누는 것이 핵심이며, 분해 후에도 원래 릴레이션의 함수 종속성이 보존되고 무손실 조인이 가능해야 한다.

Q1. 데이터베이스 설계 단계는 사용자의 요구조건에서부터 데이터베이스 구조를 도출해 내는 과정을 의미한다. 데이터베이스 설계에서 일반적으로 요구조건 분석 단계가 끝나면 개념적 설계(Conceptual Design) 단계가 시작된다. 이러한 개념적 설계 단계에 대한 설명 중 가장 적절하지 않은 것은 ? (2011, 원본 p.7)
  1. 집단화(Aggregation)와 일반화(Generalization)의 추상화(Abstraction) 방법을 사용하여 개념적 스키마(Schema)를 유도한다.
  2. 개체(Entity)들 간의 연관성(Association), 즉 의미(Semantics)를 정의하는 관계성(Relationship)을 식별해서 결정한다.
  3. 개념적 스키마를 설계하는 방법 중 하나인 하향식(Top-down) 방법으로 각 부문별 뷰(View)를 식별하고 모델링한 후에 완성된 부문별 뷰들을 하나로 통합한다.
  4. 트랜잭션(Transaction)의 전체적 골격(Skeleton)을 개발하고 인터페이스를 정의한다. 또 각 트랜잭션에 대해 데이터 접근 방법과 인터페이스를 절차적으로 명세한다.
정답 ④ — 논리적 설계 단계의 트랜잭션 인터페이스 설계 시 처리 내용

Q33. 다음의 릴레이션과 함수 종속을 고려해 보자. 이 릴레이션의 현재 속한 정규형과 BCNF로 분해 후 릴레이션의 수를 올바르게 나타낸 것은? R(A,B,C,D,E), 후보키: (A,C), 함수종속: A→B, C→D, (A,C)→E (2016, 원본 p.97)
  1. 1NF, 3
  2. 2NF, 2
  3. 2NF, 3
  4. 3NF, 2
정답 ① — 복합 키 (A, C)의 부분 속성인 A와 C에서 A→B, C→D인 부분함수 종속성이 존재하므로 현재 1정규형이며, BCNF 정규화를 수행하면 R1(A, C, E), R2(A, B), R3(C, D)
Q34. 은행의 데이터베이스 시스템에서 릴레이션 R = (accno, bal), S = (accno, telno, zip)이 있다. 릴레이션 R과 S에서, accno는 계좌번호, bal은 잔액, telno는 전화번호, zip은 우편번호를 각각 나타낸다. 그리고 accno는 R과 S 각각의 키(key)이다. 이 두 릴레이션을 사용하여 "잔액이 $100 이상인 계좌의 전화번호를 알아내라"를 관계 대수(relational algebra)로 표현할 때 적합하지 않은 것은? (2014, 원본 p.67)
  1. πtelno ∧ R.accno=S.accno(σbal≥100(R×S))
  2. πtelno(σbal≥100(σR.accno=S.accno(R×S)))
  3. πtelno(σR.accno=S.accno ∧ bal≥100(R×S))
  4. πtelno(σR.accno=S.accno(σbal≥100(R×S)))
정답 ① — 프로젝트(Project, π) 연산은 주어진 릴레이션에서 속성 리스트에 제시된 애트리뷰트만 추출하는 연산으로, 표기 형식은 π(속성리스트)(R)이다. ①은 π 연산의 첨자에 조인 조건(R.accno=S.accno)이 잘못 포함되어 있어 올바른 관계대수 표기가 아니다.
Q35. 관계형 모델에서 릴레이션의 애트리뷰트(속성) 수를 가리키는 용어와, 튜플(행)의 수를 가리키는 용어를 각각 바르게 짝지은 것은? (예상문제)
  1. 차수(Degree) - 카디널리티(Cardinality)
  2. 카디널리티(Cardinality) - 차수(Degree)
  3. 도메인(Domain) - 차수(Degree)
  4. 차수(Degree) - 도메인(Domain)
정답 ① — 애트리뷰트의 수는 차수(Degree), 튜플의 수는 카디널리티(Cardinality)이며, 이 둘을 뒤바꿔 서술하는 것이 반복 출제되는 오답 패턴이다.
