1. CRC(Cyclic Redundancy Check) (원본 p.4-6)

CRC(Cyclic Redundancy Check)는 다항식 나눗셈(XOR 연산 기반)을 이용해 송신 측이 데이터에 잉여 비트를 붙여 전송하고 수신 측이 동일한 제수로 나누어 나머지가 0인지 확인함으로써 오류 유무를 검사하는 기법이다. 집단 오류(Burst Error) 검출에 가장 우수한 방식으로 꼽힌다.

CRC 코드워드는 데이터 워드에 제수(divisor)의 비트수보다 1 작은 만큼의 0을 채운 뒤, 제수로 XOR 연산(모듈로-2 나눗셈)을 반복해 나머지(remainder)를 구하고, 이 나머지를 원래 데이터 워드 뒤에 붙여서 만든다. 예를 들어 데이터 워드가 "111111"이고 제수(divisor)가 "1010"이면, XOR 연산으로 몫(quotient) "110011"과 나머지(remainder) "110"을 구해 코드워드는 "111111 110"이 된다.

2. 해밍코드(Hamming Code) (원본 p.7-10)

해밍코드는 1비트 오류를 정정할 수 있는 오류 정정 부호로, 2비트 오류가 발생하면 검출은 가능하나 정정은 어렵다는 한계가 있다. 데이터 비트 사이사이에 패리티 비트(Parity Bit)를 삽입하는데, 패리티 비트의 위치는 2p ≥ m+p+1 (m: 데이터 비트 수, p: 패리티 비트 수) 관계식을 만족하도록 정해지며 실제 위치는 20, 21, 22, …번째 자리(1, 2, 4, 8…)에 배치된다.

패리티 비트가 담당하는 검사 비트 그룹은 각자의 위치값을 2진수로 표현했을 때 해당 자릿수가 1인 데이터 비트들로 정해진다. 예를 들어 4비트 데이터에 3개의 패리티 비트(P1, P2, P3)가 붙는 7비트 코드워드에서, P1은 1·3·5·7번째 비트, P2는 2·3·6·7번째 비트, P3는 4·5·6·7번째 비트에 대해 짝수 패리티를 검사한다.

수신 측은 P1P2P3 형태로 검사 결과를 조합해 오류 비트의 위치를 바로 찾아낸다. 예를 들어 P1P2P3 = 010이면 2번째 비트에서 오류가 발생했다는 뜻이며, 000이면 오류가 없다는 뜻이다.

4. IPv6 (원본 p.17-23)

가. IPv6 개념과 주소체계

IPv6는 IPv4 주소 고갈 문제의 임시 해결책이었던 CIDR·사설 IP 주소·NAT의 도입에도 불구하고 남아 있는 기존 IP 주소 체계의 단점들을 수정·보완·대체하기 위해 만들어진 새로운 주소 체계다. 사용 가능한 주소 공간의 증대, 주소의 계층화를 통한 할당·관리 용이성, 자동적인 주소 부여 기능(Stateless Auto Configuration), 헤더의 단순화와 확장성, 종단 장비 간 통신으로의 복귀와 보안성 강화, 모바일 IPv6 기술 등이 장점으로 꼽힌다. 주소는 총 128비트를 16비트씩 8자리로 나누어 콜론(:)으로 구분해 표기하며(예: 2001:0DB8:1000:0000:0000:0000:1111:2222), 각 필드 맨 앞의 연속되는 0은 생략할 수 있고 연속되는 0 필드는 "::"로 한 번만 축약해 표현할 수 있다(예: 2001:DB8:1000::1111:2222).

나. IPv6 헤더 구조

IPv6 패킷은 기본 헤더, 확장 헤더, 상위계층 데이터의 3부분으로 구성된다. 기본 헤더는 다음 필드로 이루어진다.

필드설명
Version(4비트)IPv4이면 4, IPv6이면 6
Traffic Class(8비트)IPv6 패킷의 클래스나 우선순위를 나타내며 IPv4의 TOS(Type of Service) 필드와 유사한 기능
Flow Label(20비트)패킷들의 특정한 흐름 특성을 나타내는 필드로, 음성·화상 등 실시간 데이터 트래픽은 0이 아닌 값으로 설정
Payload Length(16비트)페이로드부의 길이(확장헤더 + 상위계층 데이터)
Next Header(8비트)기본헤더 다음에 위치하는 확장 헤더의 종류를 표시
Hop Limit(8비트)IPv4의 TTL(Time To Live)에 대응
Source/Destination Address(각 128비트)발신지와 목적지 주소

확장 헤더는 홉-바이-홉(Hop-by-Hop, 데이터그램이 거쳐 가는 모든 라우터에 소스 정보 전달), 목적지(Destination, 정보를 목적지에만 전달), 소스 라우팅(Source Routing), 단편화(Fragmentation, IPv6는 원 근원지에서만 단편화 가능), AH(발신자 인증·무결성), ESP(기밀성 보장), 이동성(MIPv6) 등으로 구분된다.

💡 Tip · 오답 포인트
  • 에러 메시지가 0~127번, 정보 메시지가 128~255번이다(반대로 서술하면 오답).
  • Packet Too Big 메시지는 Type 2이다(Type 4가 아님).
  • NDP(Neighbor Discovery Protocol)는 IPv4의 ARP와 유사한 역할이다(RARP가 아님).

나. 슈퍼네팅(Supernetting)과 CIDR

슈퍼네팅은 다수의 작은 네트워크를 하나의 큰 네트워크로 통합하는 것으로, 네트워크 정보를 요약해 라우터 테이블의 크기를 축소하고 라우터 수를 줄이는 방법이다. CIDR(Classless Inter-Domain Routing)은 IP 주소를 Classful과 같은 규격화된 구분 없이, 비트 단위의 Subnet Mask 정보도 네트워크 정보로 함께 라우팅하는 방식으로, IPv4 주소의 효율적 사용과 접두어를 이용한 계층적 주소 지정으로 광역 라우팅 부담을 줄인다.

예를 들어 IPv4 주소 168.199.160.82/27은 서브넷 마스크가 255.255.255.224이며, 호스트 식별자의 크기는 5비트이므로 서브넷은 8(23)개이고 각 서브넷의 호스트 수는 32(25)개다. 각 서브넷의 호스트 주소 범위는 168.199.160.0~31, 32~63, 64~95, 96~127, 128~159, 160~191, 192~223, 224~255로 나뉘며, 82가 속한 서브넷(64~95)의 마지막 IP 주소는 168.199.160.95다.

7. TCP/MPTCP/SCTP (원본 p.35-42)

가. TCP(Transmission Control Protocol)

TCP는 신뢰성 있는 통신을 지향하는 전송계층 프로토콜이다. 연결 설정은 3-way 핸드쉐이킹(Sync, Ack)을 사용해 양쪽이 데이터 전송 준비가 되었음을 보장하며, 연결 해제는 4-way 핸드쉐이킹(FIN, Ack)을 사용한다.

혼잡제어 단계설명
느린 출발(Slow Start)혼잡 윈도우(cwnd) 크기를 한계치(threshold)에 도달할 때까지 1→2→4→8…로 지수적으로 증가
혼잡회피(Congestion Avoidance)혼잡 상태가 감지될 때까지 혼잡 윈도우를 1씩(1,2,3,4…) 선형 증가
Multiplicative Decrease재전송 타이머 만료(Time-out) 시 threshold ≤ ½×(윈도우크기), cwnd ≤ 1로 복귀. 3개의 중복 ACK 수신 시 threshold ≤ ½×(윈도우크기), cwnd ≤ threshold로 조정
빠른 재전송(Fast Retransmission)연속된 3개의 중복 ACK 수신 시 네트워크 혼잡에 의한 손실로 간주하고 빠르게 재전송
빠른 회복(Fast Recovery)손실 발생 시 혼잡 윈도우를 손실 당시 크기의 절반으로 줄인 뒤 혼잡회피 과정으로 전송을 재개
타이머내용
재전송(Retransmission) 타이머세그먼트 전송마다 가동. 정해진 시간(RTO) 내 ACK가 없으면 재전송(RTO는 고정값이 아님)
영속(Persistence) 타이머윈도우 크기 결정을 위한 타이머. Window Probe 패킷의 송신 주기를 처리
시간 대기(Time-waited) 타이머연결 종료 후 이 시간 동안만 연결을 유지 — 지연·중복 도착 패킷을 폐기해 방지
연결 유지(Keep-alive) 타이머연결이 오랫동안 휴지 상태에 있지 않도록 함. 일반적으로 2시간 무응답 시 75초 간격으로 프로브 패킷을 10번 송신 후에도 응답이 없으면 연결 종료

나. MPTCP(Multipath TCP)

MPTCP는 단말과 TCP 서버 간에 다수의 TCP 경로를 구성하고 다수의 경로로 동시에 데이터를 송수신하는 TCP 확장형 프로토콜이다. 전송계층을 MPTCP 계층(하나의 논리적 연결로 보이도록 연결 관리)과 서브플로우 계층(논리적 연결을 경로 수만큼 나눠 각각 독립된 단일 경로 TCP처럼 취급)으로 분류한다. 초기 연결 과정은 3-way 핸드쉐이킹에 MP_CAPABLE 옵션을 포함하고, 서브플로우 추가 과정은 4단계로 이루어지며 MP_JOIN 옵션을 포함한다. 연결 해제는 TCP와 달리 각 서브플로우에서 독립적으로 FIN 패킷을 전송해야 해당 서브플로우만 종료된다(MPTCP 계층에서 한 번에 모든 연결을 해제하는 것이 아님).

다. SCTP(Stream Control Transmission Protocol)

SCTP는 UDP의 메시지 지향(message-oriented) 특성과 TCP의 연결형 신뢰성 제공 특성을 조합한 프로토콜로, 멀티스트리밍(multi-streaming) 및 멀티호밍(multi-homing)을 제공한다. 연결 설정은 4-way 핸드쉐이킹을 사용해 양 종단 간 primary IP와 대체 가능 IP 주소 목록을 교환하며, DATA Chunk에는 순서 유지가 필요 없는 경우 지연을 줄이는 U(Unordered) 플래그가 존재한다. 연결 해제는 TCP와 달리 3단계로 구성된다.

💡 Tip · 오답 포인트MPTCP의 연결 해제는 MPTCP 계층에서 한 번에 모든 연결을 끊는 것이 아니라, 각 서브플로우에서 개별적으로 FIN 패킷을 전송해 해제한다.

가. 성능 테스트 용어(TPS, Transaction Per Second)

용어설명
Response Time사용자가 서버에 요청한 시간부터 응답을 받을 때까지의 모든 시간
Think Time응답을 받은 후 웹 페이지를 보는 등 작업하는 시간

Active User현재 시스템에 트랜잭션을 실행해 부하를 주고 있는 사용자
TPS초당 처리할 수 있는 트랜잭션의 양

TPS 관련 핵심 공식은 다음과 같다: TPS = Active User / Average Response Time = Concurrent User / Request Interval. 이를 응용하면 Active User = Concurrent User × Average Response Time / (Average Response Time + Average Think Time)로 구할 수 있다. 예를 들어 10,000명이 동시 로그인해 시간당 180만 개의 비즈니스 기능을 처리한다면 TPS = 1,800,000/3,600 = 500 TPS이고, 평균응답시간 = Active User/TPS = 10,000/500 = 20초가 된다.

다. 컴퓨터 성능 계산 예제

2GHz 클럭 컴퓨터 A에서 실행시간이 10초인 프로그램을, 컴퓨터 A보다 1.2배 많은 클럭 사이클이 필요한 컴퓨터 B에서 8초에 실행시키려 할 때, 클럭주기 = 1/2GHz이므로 명령어 × CPI(A) = 20이고, 컴퓨터 B의 클럭속도 = (명령어 × 1.2×CPI(A)) / 8초 = 24/8 = 3GHz가 된다.

또 다른 예로, 실행시간 100초(CPU 시간 80초 + I/O 시간 20초)인 벤치마크 프로그램에서 CPU 시간이 CPU 개수에 정비례해 감소하고 CPU 개수가 2년마다 2배씩 증가한다면, 6년 후 CPU는 8배 증가해 CPU 시간은 10초로 줄고 I/O 시간 20초는 그대로이므로 실행시간은 30초(CPU 10초+I/O 20초)가 되며, 이때 I/O 시간이 차지하는 비율은 20/30 ≈ 66.6%다.

다. 합의 알고리즘

합의 알고리즘설명
작업증명(PoW, Proof of Work)블록 헤더 해시값을 계산해 난이도(Bits)에 따른 목표값과 비교, 만족하지 못하면 nonce를 바꿔 반복. 높은 연산능력과 물리적 에너지가 필요하며, byzantine fault를 직접 대응하는 방식은 아니고 확률적으로 문제를 완화
지분증명(PoS, Proof of Stake)토큰 지분량과 보유 시간을 통해 확률적으로 블록 생성자를 선정. 초기 코인 분배 문제와 Nothing at Stake 문제(유효 블록체인이 2개 이상일 때 양쪽에서 블록을 생성해 하나로 수렴을 어렵게 하는 문제) 발생 가능
위임된 지분증명(DPoS)PoS 기반으로 지분량에 따라 대표자(Delegate)를 선출해 순번대로 블록을 생성, 대표자에게 검증 권한을 위임
PBFT(Practical Byzantine Fault Tolerance)비동기 시스템에서 악의적 노드가 있어도 합의 가능(N=3F+1일 때 정상 동작 보장, N: 전체노드, F: Fault노드). Pre-Prepare–Prepare–Commit–Reply 단계로 진행되며, 다수결(2/3 이상)로 의사결정 후 블록 생성. 참가자 전원이 서로를 미리 알고 있어야 함
팩소스(PAXOS)과반수 동의를 얻으면 그 내용이 변경되지 않음. 리더 중심 합의를 형성하지만 Byzantine Fault 모델이 아니라 악의적 참가자가 있는 환경에는 부적합
💡 Tip · 오답 포인트
  • 컨소시엄 블록체인은 퍼블릭 블록체인에 비해 투명성과 보안성이 낮다(높다고 서술하면 오답).
  • 퍼블릭 블록체인은 프라이빗 블록체인에 비해 확장성이 낮고 거래 속도가 느리다(반대로 서술하면 오답).
  • 프라이빗 블록체인은 중앙기관이 거래를 증명하므로 PoW·PoS 같은 합의 알고리즘을 반드시 사용할 필요가 없다.

19. 기계학습(Machine Learning) (원본 p.75-78)

구분설명
지도학습(Supervised Learning)출력 결과값을 알려주는 '교사'가 존재(Label 존재). 인식·분류·진단·예측에 적합. 예: K-NN, 선형회귀, 로지스틱회귀, SVM, 결정트리, 신경망
비지도학습(Unsupervised Learning)출력 값에 대한 정보 없이(교사 없이) 학습(Label 없음). 군집화·밀도추정·차원축소·특징추출에 적합. 예: 군집(Clustering), K-평균(K-Means), 계층 군집 분석, PCA, 신경망
강화학습(Reinforcement Learning)상태(State)에서 어떤 행동(Action)이 최적인지를 학습. 행동마다 외부 환경의 보상(Reward)을 최대화하는 방향으로 학습. 예: 컴퓨터 체스, 로봇 제어

과적합(Overfitting)은 학습 데이터를 지나치게 정확히 구분하도록 학습해 모델의 일반화 성능이 떨어지는 문제로, 학습 데이터의 오차는 감소하지만 실제 데이터의 오차는 증가한다. 학습 데이터가 너무 적거나 과도하게 학습되었거나, 전체 데이터 분포를 반영하지 않을 때 주로 발생하며 모델이 복잡할수록 발생 확률이 높다. 지도학습에서는 충분한 학습 데이터 확보와 검증 데이터(validation data) 평가로, 딥러닝에서는 Dropout(연결 가중치가 높은 링크를 확률적으로 제거) 기법으로 해결한다.

💡 Tip · 오답 포인트K-Means·PCA는 비지도학습, K-NN은 지도학습 알고리즘이다 — 지도학습·비지도학습의 대표 알고리즘을 서로 뒤바꿔 서술하는 것이 전형적 오답이다.

20. 딥러닝(Deep Learning) (원본 p.79-88)

가. 단일 퍼셉트론과 다층 신경망

단일 퍼셉트론은 사람의 생물학적 뉴런 기능을 모방하기 위해 고안된 구조로, 각 뉴런은 N차원 공간에서의 선형방정식을 표현하므로 하나의 단층 퍼셉트론은 여러 선형함수의 집합으로 간주된다. 단일 퍼셉트론으로 logical-OR·logical-AND 같은 이진 논리함수는 표현할 수 있으나, logical-XOR 함수는 표현할 수 없다는 한계가 있다.

구성요소설명
입력층신경망 외부로부터 입력을 받아들이는 층 — 뉴런이 아닌 입력값을 보관하는 buffer들로 구성
은닉층외부에서 보이지 않고(hidden) 신경망 내부에서 값 전달 방식에 영향을 주는 역할
출력층신경망 외부에 측정값을 출력
완전연결(Fully Connected)다층 퍼셉트론은 인접 층 사이의 노드 간에 모든 연결선이 존재한다고 가정
feed-forward값의 전달이 한쪽 방향으로만 진행

활성화 함수로는 Linear(y=z), Sign, Sigmoid(y=1/(1+e−z)), Tanh(y=(ez−e−z)/(ez+e−z)), ReLU(y=max(0,z)), Leaky ReLU(y=max(αz,z)) 등이 사용된다.

나. CNN(Convolutional Neural Network)

컨볼루션 층(convolution layer)과 풀링층(pooling layer)을 쌍(pair)으로 구성해 fully connected layer 이전에 이미지·영상 등을 압축하는 인공신경망이다. 컨볼루션 층은 입력 이미지에서 국소적인 특징 영역의 특징값들을 종합하는 역할을 하며, 풀링 층은 이전 컨볼루션 층 노드들의 특정 영역 부분적 주요값들을 통합하는 역할을 한다. 풀링 층은 다운샘플링(down-sampling) 방식으로 영상의 크기를 줄인다(Average pooling, Max pooling).

다. RNN(Recurrent Neural Network)과 LSTM

RNN(순환 신경망)은 특정 노드의 해당 노드에 다시 연결되는 구조를 갖는 신경망으로, 현재 입력과 과거 입력을 함께 고려해 결과를 도출하는 형태다. 시계열 데이터·순차적 학습 알고리즘에 적합하며, 오랜 역전파 학습 알고리즘을 수정한 BPTT(Back-propagation Through Time) 알고리즘을 사용한다. 다만 학습 과정이 길어질수록 기울기가 소실되는 문제가 있다.

LSTM(Long Short-Term Memory)은 RNN의 기울기 소실 문제를 해결하기 위해 메모리 구조(Cell State)를 활용하는 신경망이다. Forget Gate(어떤 정보를 버릴지 결정, Sigmoid 활용), Input Gate(어떤 새 정보를 저장할지 결정, Sigmoid·tanh 활용), Output Gate(최종적으로 어떤 정보를 출력할지 결정)의 3가지 게이트 구조를 가지며, Cell State는 입력값을 거의 그대로 유지하며 전체 체인에 계속 전달된다.

💡 Tip · 오답 포인트LSTM은 Forget Gate·Input Gate·Output Gate로 구성되며, Reset Gate는 LSTM이 아니라 GRU(Gated Recurrent Unit)의 구성 요소다.

Q6. [예상문제] 전송계층(Transport Layer)에서 사용하는 프로토콜에 대한 설명으로 가장 옳지 않은 것은? (원본 p.41)
