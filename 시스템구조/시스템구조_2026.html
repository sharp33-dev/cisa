영역 2 · 정답 해설 / 오답 분석 / 이론
정답 해설

RPO(Recovery Point Objective) 는 재해 발생 시 허용 가능한 데이터 손실의 범위를 시간 단위로 정의한 지표이다(예: RPO 1시간 = 최대 1시간치 데이터 손실 허용 → 백업 주기 결정). 따라서 정답은 ①이다.

  • RTO는 복구까지 걸려도 되는 시간(가동 중단 허용 시간).
  • MTBF/MTTR은 신뢰성·정비성 지표로 재해복구 목표값이 아니다.
오답 분석

보기②

RTO는 "복구에 걸리는 허용 시간"으로, 데이터 손실 범위가 아니다.

보기③

MTBF는 고장 간 평균시간(신뢰성)이다.

보기④

MTTR은 평균 수리시간(정비성)이다.

관련 이론 정리
  • RPO: 데이터 손실 허용 시점 → 백업 주기.

  • RTO: 서비스 복구 허용 시간 → 복구 체계 수준.

  • 시험 포인트: "데이터 손실=RPO, 복구 시간=RTO".

부호를 무시하고 부호 없는 10진수(unsigned)로 해석한 값이다.

  • 2의 보수 음수 값 = 비트 반전 후 +1에 음부호.

  • 시험 포인트: MSB=1 → 음수, "반전+1" 절차.

보기

② 정규화
③ 가수 나누기
④ 지수 뺄셈

정답

정답 : ①번

정답 신뢰도 : 매우 높음 (원본 이미지 Bold 확인)

핵심 키워드
  • 부동소수점 나눗셈: 가수 나누기 + 지수 뺄셈 + 정규화
  • 지수 덧셈은 곱셈에서 필요
문제 정보
항목 내용
연도 2026년 (제27회)

영역 2 · 정답 해설 / 오답 분석 / 이론
정답 해설

부동소수점 나눗셈은 가수(mantissa)를 나누고, 지수(exponent)를 빼며, 결과를 정규화한다. 반면 지수 덧셈은 부동소수점 곱셈에서 필요한 연산이므로, 나눗셈에서 필요하지 않은 것은 ① 지수 덧셈이다.

  • 곱셈: 가수 곱하기 + 지수 더하기 + 정규화
  • 나눗셈: 가수 나누기 + 지수 빼기 + 정규화

정답 해설

문제 정보
항목 내용

영역 2 · 정답 해설 / 오답 분석 / 이론
정답 해설

Amdahl의 법칙: Speedup = 1 / ((1 − P) + P/N), P=0.85(병렬 비율), N=8.

  • 직렬 부분 = 1 − 0.85 = 0.15
  • 병렬 부분 = 0.85 / 8 = 0.10625
  • 분모 = 0.15 + 0.10625 = 0.25625

따라서 정답은 ② 3.90이다.

오답 분석

보기①③④

분모 계산(0.25625) 착오 시 나오는 값들로, 정확히는 약 3.90이다. 코어 수를 무한대로 늘려도 상한은 1/0.15 ≈ 6.67이므로 6.90(④)은 불가능하다.

관련 이론 정리
  • Amdahl 상한: N→∞ 이면 1/(1−P). P=0.85 → 최대 약 6.67배.

  • Gustafson 법칙: 문제 규모 확장 시 확장성 관점.

  • 시험 포인트: 공식 대입과 직렬 부분(1−P)의 지배적 영향.

CSMA/CA(Collision Avoidance) 는 무선 LAN(IEEE 802.11)의 매체 접근 방식으로, 전송 전 매체 감지(carrier sense) 후 충돌을 회피하기 위해 랜덤 백오프 시간만큼 대기하고, 전송 후 ACK 수신으로 성공을 확인한다(무선은 충돌 감지가 어렵기 때문). 따라서 정답은 ②이다.

  • CSMA/CD는 유선 이더넷의 충돌 "감지" 방식.
  • Token Ring·FDDI는 토큰 기반 접근 방식.
오답 분석

보기①

CSMA/CD는 유선에서 충돌을 감지(전송 중 감시)하는 방식으로 무선에는 부적합하다.

보기③④

Token Ring·FDDI는 토큰 전달 기반 결정적 접근 방식이다.

관련 이론 정리
  • CSMA/CA: RTS/CTS, 백오프, ACK로 충돌 회피(무선).

  • 숨은 단말 문제: RTS/CTS로 완화.

  • 시험 포인트: "무선=CA(회피), 유선=CD(감지)".

문제

TCP 데이터 전송 과정에서 세그먼트를 송신하고 확인응답번호로 응답받는 상황(X는 손실). 클라이언트: Seq1000/Ack3000, Seq1500/Ack3000(손실 X), Seq2000/Ack3000 → 서버: Seq3000/Ack ⓐ → 클라이언트: Seq ⓑ/Ack4000. ⓐ, ⓑ에 들어갈 번호는?

보기

① ⓐ 1500, ⓑ 1500
② ⓐ 1500, ⓑ 2000
③ ⓐ 2000, ⓑ 1500
④ ⓐ 2000, ⓑ 2500

정답

정답 : ①번

정답 신뢰도 : 매우 높음 (원본 이미지 Bold 확인 + 로직 검증)

핵심 키워드
  • TCP 누적 확인응답(cumulative ACK)
  • 손실 세그먼트 재전송
문제 정보
항목 내용
연도 2026년 (제27회)
과목 시스템구조
문항번호 92번
난이도 상
출제주제 TCP 순서번호/확인응답번호 (누적 ACK)
영역 2 · 정답 해설 / 오답 분석 / 이론
정답 해설

TCP는 누적 확인응답을 사용한다. 각 세그먼트는 500바이트(Seq 1000, 1500, 2000)이다.

  • 서버는 Seq1000(1000~1499)을 받아 다음 기대 바이트 1500 을 기대한다.
  • Seq1500이 손실(X) 되고 Seq2000이 순서 없이 도착해도, 누적 ACK는 여전히 1500 (기대하는 다음 바이트)이다.
  • 따라서 서버 세그먼트 Seq:3000 Ack:ⓐ 의 ⓐ = 1500.
  • 클라이언트는 중복 ACK(1500)에 따라 손실된 세그먼트를 재전송하므로 다음 Seq:ⓑ = 1500(재전송), Ack:4000(서버 세그먼트 확인).

따라서 ⓐ=1500, ⓑ=1500 → 정답 ①.

오답 분석

보기②③④

ⓐ가 2000이 되려면 서버가 1500 손실을 건너뛰고 확인해야 하는데, 누적 ACK는 손실 지점(1500)에 머문다. ⓑ가 2000/2500이 되려면 손실 세그먼트를 재전송하지 않는 것이므로 신뢰 전송 원리에 어긋난다.

관련 이론 정리
  • 누적 ACK: "다음에 기대하는 바이트" 번호를 반환.

  • 중복 ACK & 재전송: 손실 감지 시 해당 세그먼트 재전송(빠른 재전송).

  • 시험 포인트: 손실 시 ACK는 손실 지점에 머물고, 그 지점을 재전송.

데이터 링크 계층의 흐름 제어 방식 중 Selective Repeat ARQ를 사용할 때 프레임의 순서 번호를 표현하기 위해 4비트를 할당하였다면, 이 프로토콜이 가질 수 있는 송신 윈도우의 최대 크기는?

① 7
② 8
③ 15
④ 16

정답 : ②번

정답 신뢰도 : 매우 높음 (원본 이미지 Bold 확인 + 계산 검증)

핵심 키워드
  • Selective Repeat 최대 윈도우 = 2^(n−1)
  • Go-Back-N 최대 윈도우 = 2^n − 1
문제 정보
항목 내용
연도 2026년 (제27회)
과목 시스템구조

영역 2 · 정답 해설 / 오답 분석 / 이론
정답 해설

순서 번호가 4비트이면 전체 번호 공간은 2⁴ = 16이다. 선택적 재전송(Selective Repeat) 에서는 송신·수신 윈도우 크기의 합이 번호 공간을 넘지 않아야 하므로, 최대 윈도우 크기는 2^(n−1) = 2³ = 8 이다. 따라서 정답은 ② 8이다.

  • Go-Back-N이라면 최대 윈도우는 2ⁿ − 1 = 15.
오답 분석

보기①(7)

7은 3비트 GBN 등 다른 조건의 값이다.

보기③(15)

15는 Go-Back-N의 최대 윈도우(2ⁿ−1)이다.

보기④(16)

16은 전체 번호 공간(2ⁿ)으로, 윈도우 크기 제약을 위반한다.

관련 이론 정리
방식 최대 송신 윈도우
Go-Back-N 2ⁿ − 1
Selective Repeat 2^(n−1)
  • 시험 포인트: "SR=2^(n−1), GBN=2ⁿ−1" 구분.

영역 2 · 정답 해설 / 오답 분석 / 이론
정답 해설

OSPF(Open Shortest Path First) 는 다익스트라(SPF) 알고리즘 기반 링크 상태 라우팅 프로토콜로, AS 내부에서 사용하는 IGP 이며, 토폴로지 변화 시에만 갱신 정보를 멀티캐스트로 전송해 대역폭 효율이 높다. 설명과 일치하므로 정답은 ④이다.

  • RIP: 거리 벡터(홉 카운트), 주기적 브로드캐스트.
  • ARP: IP↔MAC 주소 변환(라우팅 프로토콜 아님).
  • BGP: AS 간 경로 벡터 프로토콜(EGP).
오답 분석

보기①

RIP은 거리 벡터 방식으로 주기적 전체 라우팅 정보 전송, 홉 수 기반이다.

보기②

ARP은 주소 변환 프로토콜로 라우팅 프로토콜이 아니다.

보기③

BGP는 AS 간(EGP) 경로 벡터 프로토콜이다.

관련 이론 정리
구분 예
거리 벡터(IGP) RIP, EIGRP
링크 상태(IGP) OSPF, IS-IS
경로 벡터(EGP) BGP
  • 시험 포인트: "링크상태·Dijkstra·IGP·멀티캐스트=OSPF".

문제

다음 설명(연결 초기화/타임아웃 후 혼잡 윈도우 크기를 1로 설정하여 전송 시작, ACK 수신마다 cwnd를 1씩 증가, 임계값 도달까지 유지)에 해당하는 TCP 혼잡 제어 알고리즘의 단계는?

③ Slow Start
④ Fast Recovery

정답 : ③번

정답 신뢰도 : 매우 높음 (원본 이미지 Bold 확인)

핵심 키워드
  • Slow Start: cwnd=1에서 시작, ACK마다 증가(지수적), ssthresh까지
문제 정보
항목 내용
연도 2026년 (제27회)
과목 시스템구조
문항번호 96번
난이도 중
출제주제 TCP 혼잡 제어 - Slow Start
영역 2 · 정답 해설 / 오답 분석 / 이론
정답 해설

Slow Start 는 연결 초기 또는 타임아웃 후 혼잡 윈도우(cwnd)를 1(MSS)로 시작하고, ACK를 받을 때마다 cwnd를 늘려(RTT당 2배로) 혼잡 임계값(ssthresh) 에 도달할 때까지 지수적으로 증가시킨다. 설명과 일치하므로 정답은 ③이다. 임계값 이후에는 혼잡 회피(Congestion Avoidance) 로 전환되어 선형 증가한다.

오답 분석

보기①

Fast Retransmission은 3개의 중복 ACK 수신 시 타임아웃 전에 재전송하는 기법이다.

보기②

Congestion Avoidance는 임계값 이후 선형 증가 단계이다.

보기④

Fast Recovery는 빠른 재전송 후 cwnd를 절반에서 재개하는 단계이다.

관련 이론 정리

  • 혼잡 제어 단계: Slow Start(지수) → Congestion Avoidance(선형) → 손실 시 Fast Retransmit/Recovery.

  • 시험 포인트: "cwnd=1 시작·지수 증가=Slow Start".

출제주제 IPv6 확장헤더
영역 2 · 정답 해설 / 오답 분석 / 이론
정답 해설

Hop Limit 은 IPv6 기본(고정) 헤더의 필드(IPv4의 TTL에 해당)로, 확장헤더가 아니다. 반면 Fragmentation(단편화), Destination Options(목적지 옵션), ESP(암호화 보안 페이로드)는 모두 IPv6 확장헤더에 속한다. 따라서 확장헤더로 적절하지 않은 것은 ④이다.

오답 분석

보기①

Fragment 확장헤더는 단편화 정보를 담는다.

보기②

Destination Options는 목적지에서 처리할 옵션 확장헤더이다.

보기③

ESP는 IPsec의 암호화·무결성 확장헤더이다.

관련 이론 정리
  • IPv6 기본헤더 필드: Version, Traffic Class, Flow Label, Payload Length, Next Header, Hop Limit, 주소.

  • 확장헤더: Hop-by-Hop, Routing, Fragment, AH, ESP, Destination Options.

  • 시험 포인트: "Hop Limit=기본헤더 필드(확장헤더 아님)".

영역 1 · 문제 / 보기 / 정답 · 강의 연계 / 빈출도 / 암기
문제

대역폭이 3000Hz인 통신 채널에서 신호 대 잡음비가 31일 때 섀넌 정리에 따른 이론적 최대 전송률은? (백색 잡음, SNR은 dB가 아닌 순수 비율)

보기

① 15000 bps
② 30000 bps
③ 45000 bps
④ 93000 bps

정답

정답 : ①번

정답 신뢰도 : 매우 높음 (원본 이미지 Bold 확인 + 계산 검증)

핵심 키워드
  • Shannon: C = B · log₂(1 + S/N)
문제 정보
항목 내용
연도 2026년 (제27회)
과목 시스템구조
문항번호 98번
난이도 상
출제주제 섀넌 채널 용량(Shannon Capacity)
영역 2 · 정답 해설 / 오답 분석 / 이론
정답 해설

섀넌 채널 용량: C = B · log₂(1 + S/N).
- B = 3000Hz, S/N = 31
- C = 3000 · log₂(1 + 31) = 3000 · log₂(32) = 3000 · 5 = 15000 bps

따라서 정답은 ① 15000 bps이다.

오답 분석

보기②③④

log₂(32)=5를 다른 값으로 오산하거나(예: log₂ 대신 다른 밑) 대역폭을 잘못 곱한 값들이다. 정확히는 3000×5=15000.

관련 이론 정리
  • 섀넌 정리: 잡음 있는 채널의 이론적 최대 용량(오류 없는 전송 한계).

  • 나이퀴스트: 무잡음 채널 C = 2·B·log₂(M).

  • 시험 포인트: log₂(1+SNR) 계산, log₂(32)=5.

문제

사전 학습된 대규모 모델의 구조를 그대로 유지하면서 필요한 만큼만 파라미터를 효율적으로 수정하는 기술로 가장 적절한 것은?

보기

① RLHF(Reinforcement Learning from Human Feedback)
② LoRA(Low-Rank Adaptation)
③ RAG(Retrieval-Augmented Generation)
④ Few-shot Prompting

정답

정답 : ②번

정답 신뢰도 : 매우 높음 (원본 이미지 Bold 확인)

핵심 키워드
  • LoRA = 파라미터 효율적 미세조정(PEFT), 저랭크 행렬만 학습
문제 정보
항목 내용

출제주제 LLM 파라미터 효율적 미세조정 - LoRA
영역 2 · 정답 해설 / 오답 분석 / 이론
정답 해설

LoRA(Low-Rank Adaptation) 는 사전학습 모델의 가중치는 동결(그대로 유지) 하고, 각 층에 저랭크(low-rank) 행렬을 추가해 그 작은 파라미터만 학습하는 파라미터 효율적 미세조정(PEFT) 기법이다. 설명과 일치하므로 정답은 ②이다.

  • RLHF: 사람 피드백 기반 강화학습 정렬.
  • RAG: 외부 지식 검색을 결합한 생성.
  • Few-shot Prompting: 예시를 프롬프트에 제공(학습 아님).
오답 분석

보기①

RLHF는 모델 정렬을 위한 강화학습 방법으로 파라미터 효율적 미세조정 기법이 아니다.

보기③

RAG는 검색 결과를 참조해 생성하는 구조로 파라미터 수정과 무관하다.

보기④

Few-shot Prompting은 파라미터를 수정하지 않고 프롬프트로 유도한다.

관련 이론 정리
  • PEFT: LoRA, Adapter, Prefix/Prompt Tuning 등(소수 파라미터만 학습).

  • 장점: 저장·연산 비용 절감, 다중 태스크 어댑터 교체.

  • 시험 포인트: "구조 유지·소수 파라미터 학습=LoRA".

영역 1 · 문제 / 보기 / 정답 · 강의 연계 / 빈출도 / 암기
문제

도커 컨테이너(Container)와 가상 머신(Virtual Machine)의 차이점에 대한 설명으로 가장 적절한 것은?

보기

① 컨테이너는 하드웨어 수준의 가상화를 제공하여 보안성이 가상 머신보다 뛰어나다.
② 가상 머신은 하이퍼바이저 없이 작동하며, 컨테이너는 반드시 하이퍼바이저가 필요하다.
③ 가상 머신은 호스트 OS의 커널을 공유하지만, 컨테이너는 독립된 커널을 포함한다.
④ 컨테이너는 가상 머신보다 오버헤드가 적고 시작 속도가 매우 빠르다.

정답

정답 : ④번

정답 신뢰도 : 매우 높음 (원본 이미지 Bold 확인)

핵심 키워드
  • 컨테이너: 호스트 OS 커널 공유, 경량·빠른 기동
  • VM: 하이퍼바이저 + 게스트 OS(무거움)
문제 정보
항목 내용
연도 2026년 (제27회)
과목 시스템구조
문항번호 100번
난이도 중
출제주제 컨테이너 vs 가상머신
영역 2 · 정답 해설 / 오답 분석 / 이론
정답 해설

컨테이너 는 호스트 OS의 커널을 공유하고 애플리케이션과 의존성만 격리하므로, 게스트 OS 전체를 부팅하는 가상 머신보다 오버헤드가 적고 시작 속도가 매우 빠르다. 따라서 정답은 ④이다.

나머지는 반대로 서술되어 틀리다:
- ①: 하드웨어 수준 가상화·강한 격리는 오히려 VM 쪽이다(컨테이너는 커널 공유로 격리 수준이 상대적으로 낮음).
- ②: 하이퍼바이저는 VM에 필요하다(컨테이너는 컨테이너 런타임 사용).
- ③: 커널을 공유하는 것은 컨테이너이고, VM이 독립 커널(게스트 OS)을 가진다(서술이 반대).

오답 분석

보기①

하드웨어 가상화·강한 격리는 VM의 특징이다.

보기②

하이퍼바이저가 필요한 것은 VM이다.

보기③

커널 공유=컨테이너, 독립 커널=VM으로 서술이 반대이다.

관련 이론 정리
구분 컨테이너 가상 머신
격리 OS 수준(커널 공유) 하드웨어 수준(하이퍼바이저)
무게/기동 경량/빠름 무거움/느림
게스트 OS 없음 있음
  • 시험 포인트: "컨테이너=커널 공유·경량·빠름, VM=하이퍼바이저·게스트OS".
