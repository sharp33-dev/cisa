1. IPSec (원본 p.1-6)

IPSec(IP Security)은 네트워크 계층(3계층)에서 IP 패킷을 보호하기 위해 IETF가 정의한 프로토콜 집합으로, IPv4와 IPv6를 모두 지원한다.

구분구성 요소설명
헤더AH(Authentication Header)인증데이터와 순서번호를 통해 송신자 인증과 메시지 무결성을 검증(기밀성은 제공하지 않음)
ESP(Encapsulating Security Payload)IP 페이로드를 암호화하여 데이터 기밀성을 제공하며, 인증 옵션을 함께 사용하면 데이터 원본 인증·무결성·재연공격 방지까지 제공
키 교환IKE(ISAKMP/Oakley)두 통신 개체 간의 인증, 키 및 보안 관련 사항(SA)을 자동으로 협상·설정
모드전송(Transport)IP 페이로드만 암호화하여 원래의 IP 헤더로 캡슐화. LAN-to-LAN VPN 등에 사용
터널(Tunnel)IP 헤더를 포함한 IP 패킷 전체를 암호화하여 새로운 IP 헤더로 캡슐화 — 원래의 목적지 정보가 외부에 노출되지 않음
암호/인증 알고리즘암호 알고리즘 / 인증 알고리즘DES, 3DES, RC5 등 / MD5, SHA-1 등
💡 Tip · 오답 포인트
  • 인증은 AH, 암호화(기밀성)는 ESP가 담당한다 — 두 헤더의 역할을 바꿔 서술하는 것이 전형적 오답이다.
  • 목적지 IP까지 포함한 패킷 전체를 숨겨야 할 때(예: 최종 목적지 노출 방지)는 ESP 터널 모드를 사용한다.
  • AH는 순서번호(Sequence Number)를 이용해 재연(Replay) 공격을 방지한다.

2. SSL/TLS (원본 p.6-13)

SSL(Secure Socket Layer)은 웹 환경에서 브라우저와 웹 서버 간에 안전한 데이터 전송을 위한 업계 표준 프로토콜로, TCP/IP 계층(전송 계층)과 응용 계층(Application) 사이에 위치하여 종단 간(End-to-End) 서비스를 제공하며 서버·클라이언트 상호 인증과 기밀성을 지원한다. SSL은 상위계층의 Handshake Protocol · Change Cipher Spec Protocol · Alert Protocol과, 하위계층의 Record Protocol 4가지로 구성된다.

프로토콜역할
Handshake Protocol클라이언트-서버 간 상호 인증 및 보안 속성(암호 규격 등) 협상
Change Cipher Spec Protocol협상된 암호 규격·키로 이후 메시지를 보호하도록 지시
Alert Protocol다양한 에러·경고 메시지 전달
Record ProtocolHandshake에서 생성된 세션 정보를 이용해 실제 데이터를 단편화·압축·MAC 계산·암호화하여 보호(하위 계층에서 응용 계층 프로토콜을 캡슐화)

가. SSL Handshake 절차

Handshake 단계에서는 SSL 버전 번호, 암호화 방법, 임의의 수(Random), 데이터 압축 방법 등 통신에 필요한 정보를 주고받는다. 대표적인 메시지 흐름은 다음과 같다.

단계메시지설명
1Client Hello → Server Hello클라이언트·서버가 지원 가능한 SSL 버전, 암호 스위트, Random 값을 교환
2Certificate, Server Key Exchange, Certificate Request, Server Hello Done서버가 자신의 인증서와 키 교환 정보를 전달(서버 인증 정보), 필요 시 클라이언트 인증서를 요청
3Certificate, Client Key Exchange, Certificate Verify클라이언트가 자신의 인증서와 키 교환 정보를 전달(클라이언트 인증 정보) — 서버가 클라이언트 인증서를 요구했을 때만 필요
4Change Cipher Spec, Finished (양방향)협상된 암호 규격 적용을 알리고 Handshake 종료를 확인

키 교환 알고리즘 종류와 무관하게 클라이언트 키 교환(Client Key Exchange) 메시지는 세션키 생성에 필요한 정보를 서버에 전달해야 하므로 반드시 전송되어야 한다. 반면 서버·클라이언트 인증서는 상호 인증이 요구되는 경우에만 전송되는 선택적 메시지다.

💡 Tip · 오답 포인트
  • SSL은 메시지 암호화 + 서버 인증 + 클라이언트 인증(상호 인증)을 모두 제공한다.
  • 세션키는 Handshake Protocol에서 생성되며, Record Protocol은 그 세션키로 암호화를 수행하는 역할이지 직접 세션키를 생성하지는 않는다.
  • SSL Record Protocol은 기밀성과 무결성은 제공하지만 부인 방지(non-repudiation)는 제공하지 않는다. 처리 순서는 단편화 → 압축 → MAC 계산 → 암호화 순이다.
  • 세션 재개(재시작) 시에는 새 마스터 비밀값을 생성할 필요가 없고, 송신용·수신용 암호키가 반드시 같을 필요도 없으며, 압축이 필요할 때는 암호화 이전에 수행한다.

3. VPN (원본 p.14-18)

가. VPN(Virtual Private Network)의 정의

VPN은 네트워크와 네트워크 간에 가상의 터널을 생성하여 물리적으로 서로 연결된 것처럼 보이게 하는 기술로, 유연한 확장성·저비용·안전한 통신이라는 장점이 있다. 라우터나 방화벽에 VPN 기능을 내장하거나 전용 VPN 장비로 구현하며, 대표 유형으로 IPSec VPN과 SSL VPN이 있다.

구성 기술설명
TunnelingVPN 내의 두 호스트 간에 가상 경로를 설정. PPTP, L2TP, IPSec 등이 사용됨
Authentication, Encryption가상 경로를 다른 인터넷 사용자로부터 격리하여 안전한 채널을 생성
Access ControlVPN 내부 자원에 대한 접근을 통제

나. IPSec VPN vs SSL VPN 비교

비교 항목IPSec VPNSSL VPN
설치본사 및 지사 장비 + 클라이언트 소프트웨어 필요본사 장비만 설치, 웹 브라우저가 암호화 수행
비용본사·지사 장비 및 별도 클라이언트 소프트웨어 구매 비용 발생본사 장비만 설치하고 웹 브라우저를 사용하므로 상대적으로 저비용
보안 접속모든 IP 패킷에 대한 보안 지원(OSI 7계층 중 3계층, 네트워크 계층)가장 널리 쓰이는 웹 트래픽 보안(OSI 7계층 중 4계층, 전송 계층)
💡 Tip · 오답 포인트VPN 구현 프로토콜에는 SSL·IPSec·L2F(Layer 2 Forwarding) 등이 있으나, IMAP(메일 수신 프로토콜)은 VPN 구현과 무관하다.

4. 무선 보안 (원본 p.18-26)

가. 무선 랜 취약점

취약점설명
무선 AP DDoS/도청가용성·기밀성 침해
무선 AP 설정 노출관리자 권한 획득, 동일망 내 통신 도청, 악성코드 유포
불법 AP망에 연결된 단말기의 통신 도청, 악성코드 유포, 정보 유출
무선 랜 인증/데이터 암호화 취약취약한 암호 알고리즘 사용으로 인한 로그인 우회

나. WEP(Wired Equivalent Protocol)의 취약점

WEP은 64비트 키(40비트 WEP 공유 비밀키 + 24비트 초기화 벡터 IV)를 이용한 RC4 스트림 암호화 방식으로 무선 데이터를 보호하는 초기 방식이다.

WEP은 짧은 길이의 초기화 벡터(IV)를 사용해 재사용 가능성이 높고, 불완전한 RC4 암호 알고리즘과 고정된 키 값으로 인해 암호키가 노출될 가능성이 있으며, 짧은 길이의 암호키로 인해 전송 데이터가 노출될 위험이 있다. 이러한 문제로 WEP은 인증·접근제어 기능은 갖추고 있으나 안전한 프로토콜로 평가받지 못한다.

다. WPA/WPA2

WEP보다 보안이 강화된 신뢰성 있는 무선 네트워크를 RSN(Robust Security Network)이라 하며, IEEE 802.11i에서 규정한다. 고정된 PSK(사전 공유키) 값은 유추가 가능하므로 최소 20자 이상의 비밀키를 사용하거나, 별도의 인증 서버(RADIUS)를 운영할 것을 권고한다.

구분Pre-RSNRSN(WPA/WPA2)
암호 방식WEP-40, WEP-104TKIP(WPA1, RC4 알고리즘 기반) / CCMP(WPA2, 블록 사이퍼 알고리즘 기반)
인증 방식Open, Shared KeyPSK(WPA-Personal) 또는 802.1X/EAP 계열(EAP-TLS, EAP-TTLS, PEAP, EAP-FAST 등, WPA-Enterprise·RADIUS 인증서버 사용)
💡 Tip · 오답 포인트WPA2 Enterprise 모드는 암호화에 CCMP, 인증에 EAP(RADIUS 인증서버)를 사용한다(PSK는 Personal 모드에서 사용).

라. WTLS(Wireless Transport Layer Security)

WTLS는 IETF의 TLS 프로토콜을 기반으로 무선 환경에 적합하도록 개발된 보안 프로토콜로, X.509·WTLS 인증서·X9.68 인증서 등 다양한 인증서 규격을 지원한다. SSL과 유사하게 Handshake Protocol · Change Cipher Spec Protocol · Alert Protocol · Record Protocol로 구성되며, 데이터 무결성 · 프라이버시(기밀성) · 인증 · DoS 프로텍션(재전송되거나 성공적으로 검증되지 않은 데이터의 검출·거부)을 모두 제공한다.

마. 블루투스 공격 유형

공격 유형설명
블루프린팅(Blueprinting)공격 대상이 될 블루투스 장치를 검색하는 사전 정보 수집 단계
블루재킹(BlueJacking)/블루재밍(BlueJamming)무선 신호를 이용해 전파 방해(재밍)를 일으키는 공격
블루스나핑(BlueSnarfing)블루투스 장치끼리 인증 없이 정보를 교환할 수 있는 OPP(OBEX Push Profile) 기능을 악용해, 소유자 동의 없이 다른 블루투스 장치의 주소록·달력 등 파일에 접근하는 공격
블루버깅(BlueBugging)블루투스 장치의 통제권을 탈취해 도청하거나 임의로 조작하는 공격

Q1. [2010년 기출] IPSec(Internet Protocol Security) 내의 프로토콜들에 대한 설명이다. 가장 적절하지 않은 것은? (원본 p.2-3)
  1. IP AH(Authentication Header)는 데이터 기밀성, 데이터 무결성, 재연(Replay) 공격 보호 등을 제공한다.
  2. IP ESP(Encapsulation Security Payload)는 데이터의 기밀성, 데이터 원본 인증, 데이터 무결성, 재연(Replay) 공격 보호 등을 제공한다.
  3. IKE(Internet Key Exchange)는 IPSec의 통신개체 사이에서 SA(Security Association)를 설정하기 위해 공유된 비밀키와 인증키를 설정한다.
  4. ISAKMP(Internet Security Association and Key Management Protocol)은 보안 협상과 그들의 암호화 키들을 관리하기 위해서 자동적으로 설정하는 방법을 제공한다.
정답 ① — AH는 데이터 기밀성이 아니라 인증과 메시지 무결성 검증을 위한 인증데이터와 순서번호를 제공한다(기밀성은 ESP의 역할).
Q2. [2011년 기출] IPSec에 대한 설명으로 잘못된 것은? (원본 p.2-3)
  1. ESP 프로토콜을 인증과 함께 사용시 AH 프로토콜보다 더 나은 보안성을 보장한다.
  2. 전송모드와 터널모드를 모두 지원한다.
  3. 기본적으로 AH 프로토콜은 암호화를 지원하고, ESP 프로토콜은 인증을 지원한다.
  4. ESP에서 인증은 옵션이다.
정답 ③ — 설명이 뒤바뀌었다. AH 프로토콜은 인증을, ESP 프로토콜은 암호화(기밀성)를 지원한다.
Q3. [2013년 기출] 다음 중 조직의 LAN 게이트웨이에 VPN 서버를 설치하고 IP 패킷(고유 IP 데이터그램: IP header와 IP payload 모두)의 최종 목적지가 인터넷 상에서 노출되지 않도록 하기 위한 IPSec의 설정으로 다음 중 가장 적절한 것은? (원본 p.4-5)
  1. AH 트랜스포트 모드
  2. ESP 트랜스포트 모드
  3. AH 터널 모드
  4. ESP 터널 모드
정답 ④ ESP 터널 모드 — 전체 IP 패킷(헤더 포함)을 암호화해 목적지 정보까지 은닉하는 것은 터널 모드이며, 데이터 기밀성 자체는 ESP가 제공한다.
Q4. [2014년 기출] IPSec에 대한 설명으로 틀린 것은? (원본 p.4-5)
  1. 네트워크 계층에서 패킷을 보호하기 위한 목적으로 IETF(Internet Engineering Task Force)가 정의한 프로토콜 집합이다.
  2. IPv4와 IPv6 둘 다 지원 가능하다.
  3. AH(Authentication Header) 프로토콜과 ESP(Encapsulation Security Payload) 프로토콜은 모두 메시지 인증 서비스를 제공할 수 있다.
  4. AH 프로토콜은 재사용 공격 보호를 위한 서비스는 지원하지 않는다.
정답 ④ — AH 프로토콜은 순서번호(Sequence Number)를 이용해 재사용(Replay) 공격 보호 서비스를 지원한다.
Q5. [2010년 기출] SSL(Secure Socket Layer)이 제공하는 기능을 바르게 설명한 것은? (O: 제공, X: 제공하지 않음 — 순서: 클라이언트와 서버 간의 메시지 암호화 / 서버를 인증하기 / 클라이언트를 인증하기) (원본 p.8-9)
  1. X, O, X
  2. X, O, O
  3. O, X, O
  4. O, O, O
정답 ④ O, O, O — SSL은 메시지 암호화와 더불어 서버 및 클라이언트에 대한 상호 인증을 모두 제공한다.
Q6. [2011년 기출] SSL(Secure Socket Layer)은 2개의 계층(Application, Transport) 사이에서 4가지의 프로토콜로 구성된다. 다음 중 레코드 프로토콜을 틀리게 설명한 것은? (원본 p.10-11)
  1. Handshake Protocol에서 생성된 세션 정보를 이용하여 보안 서비스를 제공하는 프로토콜
  2. 레코드 프로토콜은 서버와 클라이언트 양쪽 모두 세션키를 생성
  3. 응용 계층에 보안서비스 제공, 상위레벨의 프로토콜을 캡슐화(Encapsulation)
  4. 암호화, 다이제스트, 데이터 압축, MAC 생성을 통해 실제 암호문 생성
정답 ② — 세션키는 Handshake Protocol에서 생성되며, Record Protocol은 이미 협의된 암호 규격·키로 암호화를 수행하는 역할이다.
Q7. [2012년 기출] 다음 중 SSL의 핸드쉐이크 프로토콜을 수행하는 과정에서 키 교환 알고리즘의 종류와 관계없이 반드시 전송되어야 하는 메시지는? (원본 p.10-11)
  1. 서버 인증서(server certificate)
  2. 서버 키 교환(server key exchange)
  3. 클라이언트 인증서(client certificate)
  4. 클라이언트 키 교환(client key exchange)
정답 ④ 클라이언트 키 교환 — 세션키 생성에 필요한 정보를 서버에 전달하는 필수 메시지이며, 나머지는 상호 인증이 요구될 때만 선택적으로 전송된다.
Q8. [2013년 기출] 다음 중 SSL 프로토콜의 동작에 대한 설명으로 가장 적절한 것은? (원본 p.12-13)
  1. 일시 중지한 세션을 재시작하려면 반드시 마스터 비밀값(master secret)을 생성해야 한다.
  2. 클라이언트의 데이터 송신용(write) 암호키와 수신용(read) 암호키가 반드시 동일해야 한다.
  3. 핸드쉐이크(handshake) 과정에서 서버는 반드시 클라이언트의 인증서를 요구해야 한다.
  4. 전송 데이터에 대한 압축이 필요한 경우는 반드시 암호화 이전에 압축을 수행해야 한다.
정답 ④ — 압축은 암호화 이전에 수행해야 한다. 세션 재개 시 마스터 비밀값 재생성은 불필요하고, 송수신 암호키가 같을 필요도 없으며, 클라이언트 인증서 요구는 선택 사항이다.
Q9. [2015년 기출] SSL(Secure Socket Layer)에 관한 설명 중 틀린 것은? (원본 p.12-13)
  1. SSL 레코드 프로토콜은 기밀성과 메시지 무결성, 부인 방지 서비스를 제공한다.
  2. SSL 레코드 프로토콜은 단편화, 압축, 메시지 인증 코드 계산, 암호화의 순서로 수행된다.
  3. SSL은 TCP를 이용하여 신뢰할 수 있는 종단-대-종단 보안 서비스를 제공하기 위해 설계되었다.
  4. 경고(Alert) 프로토콜은 SSL 관련 경고를 전달하기 위해 사용된다.
정답 ① — SSL 레코드 프로토콜은 기밀성과 메시지 무결성은 제공하지만 부인 방지(non-repudiation) 서비스는 제공하지 않는다.
Q10. [2014년 기출] VPN 구현을 위해 사용하는 프로토콜과 가장 거리가 먼 것은? (원본 p.16-17)
  1. SSL(Secure Socket Layer)
  2. IMAP(Internet Message Access Protocol)
  3. IPSec(IP Security Protocol)
  4. L2F(Layer 2 Forwarding)
정답 ② — IMAP은 메일 수신을 위한 프로토콜로, VPN 구현 프로토콜과는 무관하다.
Q11. [2010년 기출] 무선 보안에 사용되는 WEP에 대한 설명으로 가장 적절한 것은? (원본 p.23-24)
  1. "Wireless Ethernet Privacy"의 축약어이다.
  2. 무선 환경에서 매우 안전한 프로토콜로 평가받고 있다.
  3. 기본적으로 RC4 스트림 암호를 이용한다.
  4. 암호화를 통한 기밀성을 제공하고 있지만 인증이나 접근 제어 기능은 없다.
정답 ③ — WEP는 Wired Equivalent Protocol의 약자이며, RC4 스트림 암호를 이용한다. 여러 취약점으로 인해 안전한 프로토콜로 평가받지 못하며, 인증·접근제어 기능도 갖추고 있다.
Q12. [2012년 기출] 무선랜의 보안이 WPA-2이고 Enterprise 모드로 동작하고 있을 때, 암호화와 인증이 가장 적절하게 짝지어진 것은? (원본 p.23-24)
  1. TKIP와 PSK 인증
  2. TKIP와 EAP 인증
  3. CCMP와 PSK 인증
  4. CCMP와 EAP 인증
정답 ④ CCMP와 EAP 인증 — WPA2는 CCMP(블록 사이퍼) 암호화를 사용하며, Enterprise 모드는 RADIUS 서버를 통한 EAP 인증을 사용한다(PSK는 Personal 모드).
Q13. [2014년 기출] 무선 전송계층 보안 프로토콜인 WTLS에 대한 설명으로 가장 거리가 먼 것은? (원본 p.25-26)
  1. TLS(Transport Layer Security)에 기반한 무선 보안 프로토콜이다.
  2. 프라이버시, 인증은 제공하지만 무결성 및 부인방지 서비스는 제공하지 않는다.
  3. 서비스 제공을 위하여 Handshake Protocol, Alert Protocol, Change Cipher Spec Protocol, Record Protocol을 포함한다.
  4. 인증을 위하여 WTLS 인증서와, X9.68 인증서, X.509 인증서를 지원한다.
정답 ② — WTLS는 데이터 무결성·프라이버시·인증·DoS 프로텍션을 모두 제공한다(무결성을 제공하지 않는다는 서술이 틀림).
Q14. [2014년 기출] 블루투스 장치끼리 인증 없이 정보를 교환할 수 있는 OPP(OBEX Push Profile) 기능을 이용하여 다른 블루투스 장치의 주소록, 달력 등의 내용을 열람하거나 파일에 접근하는 공격은? (원본 p.25-26)
  1. 블루프린팅(Blueprinting)
  2. 블루재밍(BlueJamming)
  3. 블루스나핑(BlueSnarfing)
  4. 블루버깅(BlueBugging)
정답 ③ 블루스나핑 — OPP 기능을 악용해 소유자 동의 없이 파일·개인정보에 접근하는 공격이다. 블루프린팅은 사전 정보수집, 블루재밍은 전파방해, 블루버깅은 장치 통제권 탈취(도청)를 의미한다.
