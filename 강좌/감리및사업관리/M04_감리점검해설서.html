1. 정보시스템 감리 점검 해설서(V3) – 개요 및 구조

감리 점검 해설서는 감리원이 사업유형별로 무엇을 어떻게 점검할지 정한 감리 점검 프레임워크다. 감리는 다음 3계층 구조로 수행된다.

사업유형 (ITA·ISP·SD·DB·OP·MA·PM) → 감리시점/단계 (분석·설계·구현·시험·전개 등) → 점검영역 (시스템아키텍처·응용시스템·데이터베이스·품질보증활동) → 점검항목 (충분성·적정성·완전성·추적성 등)
💡 Tip · 핵심 축 시스템개발(SD)의 점검영역 4가지 = 시스템아키텍처(SA) · 응용시스템(AP) · 데이터베이스(DB) · 품질보증활동(QA). 점검항목의 서술어(충분성·적정성·완전성·추적성·일관성)가 반복된다. 감리 사업유형 코드(ITA/IS/SD/DB/OP/MA/PM)와 각 유형의 단계 구성을 함께 암기한다.

2. 감리 사업유형 (점검 대상 유형)

감리는 사업의 성격에 따라 사업유형을 나누고, 각 유형별로 감리시점(단계)·점검영역·점검항목을 적용한다.

코드사업유형감리시점(단계) 구성
ITA정보기술아키텍처 구축기반정립·현행 아키텍처 구축 / 목표 아키텍처 구축·이행계획 수립 / 관리체계
IS(ISP)정보화전략계획 수립현황분석·전략수립(업무·기술) / 개선모델·실행계획 수립
SD시스템개발분석 / 설계 / 구현 / 시험 / 전개 (모델: 구조적·정보공학 / 객체지향·컴포넌트)
DB데이터베이스 구축준비(데이터수집·시범구축) / 구축(데이터구축·품질검사)
OP운영운영실행(서비스제공·서비스지원)
MA유지보수유지보수이행
PM사업관리착수·계획 / 실행통제 / 종료
Q. 정보시스템 감리 점검 해설서의 사업유형과 코드 연결이 틀린 것은?
  1. ITA – 정보기술아키텍처 구축
  2. IS – 정보화전략계획 수립
  3. MA – 데이터베이스 구축
  4. OP – 운영
정답 ③ — MA는 유지보수(Maintenance)이고, 데이터베이스 구축은 DB이다.

3. 시스템개발(SD) – 구조적·정보공학 모델

단계(분석→설계→구현→시험→전개) × 점검영역(시스템아키텍처·응용시스템·데이터베이스·품질보증활동)으로 점검한다.

단계점검영역별 핵심 점검 내용
분석시스템아키텍처: 운영환경 분석, 기술 아키텍처 구성·용량 / 응용시스템: 프로세스·이벤트 모델링, 기능 도출 / 데이터베이스: 엔티티 정의·관계 설정 등 데이터 모델링
설계SA: 상세설계, 설치·검증·전환 계획 / AP: 프로그램 분할, UI·인터페이스 설계, 단위시험 계획 / DB: 테이블·성능·접근통제·백업복구·초기데이터·전환 설계
구현SA: 도입/설치·보안환경 구축, 시험계획 / AP: 업무기능 구현(충분성·완전성), 단위·통합시험 / DB: 테이블 구현, 성능·접근통제, 정합성 검증
시험통합시험·시스템시험(기능 완전성·성능·안전성·보안성), 최적화, 사용자/운영자 지침서, 인수시험 계획
전개운영준비 – 운영환경 설치·배포, 초기데이터 구축·전환·검증, 시스템·업무 전환, 사용자 인수시험
💡 Tip · SD 점검영역 암기 모든 개발 단계에서 시스템아키텍처 · 응용시스템 · 데이터베이스 3영역 + 품질보증활동이 공통으로 점검된다. 품질보증활동의 단골 항목: 방법론·절차·표준 준수, 사용자요구사항과 산출물 간 추적성·일관성.

4. 시스템개발(SD) – 객체지향·컴포넌트기반 모델

반복적 개발 특성에 맞춰 요구분석 → 분석설계 → 구현 단계로 구성되며, 각 반복(iteration)마다 품질보증활동을 점검한다.

단계핵심 점검 내용
요구분석상위 수준 개념적 시스템 아키텍처 정의, 유스케이스 모형 정의·분석 클래스 도출, 개념적 엔티티 클래스 도출
분석설계아키텍처 프로토타이핑·기술검증, 유스케이스·분석 클래스 정제·상세설계, 컴포넌트 도입/구현 상세설계
구현컴포넌트 도입/개발 구현, 단위·통합시험, 데이터 무결성·성능·보안 구현
품질보증활동반복계획 수립·평가, 방법론/절차/표준 준수, 총괄시험 계획, 추적성·일관성, 사업목표 달성 여부
💡 Tip 객체지향·컴포넌트 모델은 유스케이스 모형·분석 클래스·컴포넌트가 키워드다. 구조적/정보공학 모델(프로세스·이벤트 모델링, 엔티티-관계)과 산출물이 다르므로 구분한다.

5. 정보기술아키텍처(ITA) 구축

정보기술아키텍처(ITA/EA) 구축 감리는 현행·목표 아키텍처의 정의와 이행계획·관리체계를 점검한다.

감리시점점검영역
기반정립·현행 아키텍처 구축환경분석·추진방향·원칙·프레임워크 정립 / 현행 업무·응용·데이터·기술·보안 아키텍처 정의, 상호 연관성·정합성, 성숙도 진단 / 품질보증활동
목표 아키텍처 구축·이행계획 수립목표 아키텍처 정의·일관성·추적성 / 이행과제 도출·이행계획·법제도 개선방안 / 관리체계(활용·관리·성과평가체계 일관성) / 품질보증활동
💡 Tip · 아키텍처 5종 현행·목표 아키텍처는 업무 · 응용 · 데이터 · 기술 · 보안 5개 관점으로 정의한다. ITA의 최종 산출물 활용을 위한 관리체계(활용·관리·성과평가) 점검이 특징.

6. 정보화전략계획(ISP) 수립

정보화전략계획(ISP) 수립 감리는 현황분석·전략수립과 개선모델·실행계획 수립의 적정성을 점검한다.

감리시점점검영역·내용
현황분석·전략수립업무: 조직 목표·전략 식별, SWOT, 핵심성공요소, 개선과제 도출 / 기술: 응용·데이터·시스템 아키텍처 분석, 보안정책·위험분석, 정보기술 평가 / 품질보증활동
개선모델·실행계획 수립업무·시스템·보안·정보자원관리 개선모델 도출, 법제도 개선, 정보화 성과관리 체계, 전환계획, 정보화 실행계획(구체적·실현가능)
💡 Tip ISP는 현황분석(업무·기술) → 개선모델·실행계획 흐름. SWOT·핵심성공요소(CSF)·개선과제가 업무 영역의 핵심 점검 포인트.

7. 데이터베이스(DB) 구축

데이터베이스(DB) 구축 감리는 준비(수집·시범구축)와 구축(데이터구축·품질검사) 단계를 점검한다.

단계점검영역·내용
준비데이터수집 및 시범구축 – 구축대상 조사·선정, 구축요건·계획, 품질기준·검사지침, 구축공정·작업지침, 시범구축 검증, 원시자료 수집·관리, 작업자 교육
구축데이터구축 – 작업지침 확정·관리, 공정 진척·작업장 관리, 정확한 구축, 구축량 목표 달성 / 품질검사 – 전수/표본 검사, 품질목표 달성
💡 Tip · 추가 고려사항 전자화된 자료를 새 포맷으로 변환하는 사업은 신규 구축과 구분 점검. 연차 연속사업은 작업지침·품질기준이 기 정립됨. 구축 도구가 자체 개발 프로그램이면 프로그램·산출물의 주관기관 제공 여부를 점검.

8. 운영(OP)

운영실행 단계에서 서비스제공과 서비스지원 두 영역을 점검한다(ITIL 기반 운영관리 체계).

영역점검 내용
서비스제공운영관리 계획, SLA(서비스수준)·성과·용량 관리, 서비스 연속성(예방점검·백업복구·재해대응), 성능·가용성·보안·아웃소싱 관리
서비스지원서비스데스크, 장애·문제관리, 구성관리, 변경관리, 릴리즈관리, 의사소통 관리
💡 Tip · ITIL 매핑 서비스제공 = SLA·용량·가용성·연속성(Service Delivery), 서비스지원 = 서비스데스크·장애/문제·구성·변경·릴리즈(Service Support). ITIL v2의 두 축과 정확히 대응된다.

9. 유지보수(MA)

유지보수(MA) 감리는 유지보수 절차·표준 수립과 실제 이행의 적정성을 점검한다.

영역점검 내용
유지보수이행유지보수 계획·절차·지침 수립, 요구사항 관리 효율성, 절차/지침 준수 및 결과 적정성, 구성관리·변경관리·릴리즈관리 체계
💡 Tip 유지보수의 핵심 점검 = 요구사항 관리 + 구성/변경/릴리즈 관리. 운영(OP)의 서비스지원과 관리 체계가 겹치므로 사업유형(운영 vs 유지보수)을 구분해서 이해한다.

10. 사업관리(PM)

모든 사업에 공통으로 적용되는 사업관리 감리로, 착수·계획 → 실행통제 → 종료로 진행된다.

단계점검 내용
착수·계획범위·변경·일정·자원·의사소통·위험·품질 관리체계 수립(구체적·실행가능)
실행통제범위 변경관리, 진척관리, 인력관리, 의사소통·위험·품질관리 수행
종료계획된 일정 내 사용자 요구사항 충족·정상 완료 여부
Q. 시스템개발(SD) 감리의 공통 점검영역이 아닌 것은?
  1. 시스템아키텍처
  2. 응용시스템
  3. 데이터베이스
  4. 이해관계자관리
정답 ④ — SD 점검영역은 시스템아키텍처·응용시스템·데이터베이스(+품질보증활동)이다. '이해관계자관리'는 사업관리(PM)의 관리 요소이지 SD 점검영역이 아니다.
💡 Tip · PM 관리 7요소 착수·계획에서 수립하는 관리체계 = 범위·변경·일정·자원·의사소통·위험·품질. PMBOK 지식영역과 유사하나 감리 점검은 "체계 수립의 적정성 + 실행통제의 적정성"을 본다.
