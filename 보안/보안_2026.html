정답 해설

SQL Injection 예방책은 ㄱ 파라미터화 질의(Prepared Statement), ㄴ 저장 프로시저(파라미터 처리), ㄹ 입력값 검증 이다. 반면 ㄷ 동적 SQL(Dynamic SQL) 은 문자열 결합으로 질의를 만드는 방식으로, 오히려 SQL Injection에 취약하며 예방책이 아니다(파라미터 바인딩 없이 조합하면 위험). 따라서 옳은 것은 ㄱ, ㄴ, ㄹ → 정답 ②.
SQL Injection 예방책은 파라미터화 질의(ㄱ)·저장 프로시저 파라미터 처리(ㄴ)·입력값 검증(ㄹ)이다. 반면 동적 SQL(ㄷ)은 문자열 결합으로 질의를 만들어 오히려 취약하므로 예방책이 아니다. 따라서 옳은 것은 ㄱ·ㄴ·ㄹ로 ②가 정답이다.

오답 분석

보기①③④

'ㄷ'(동적 SQL을 예방책이라 함)을 포함하거나 옳은 'ㄹ'을 누락하여 오답이다.

관련 이론 정리
  • 최우선 예방: Prepared Statement(파라미터 바인딩).

  • 보조: 저장 프로시저, 입력 검증(화이트리스트), 최소권한 계정, 오류메시지 최소화.

  • 시험 포인트: "동적 SQL=취약(예방책 아님)".

인젝션 방어 계층: ①Prepared Statement(파라미터 바인딩, 최우선)②저장 프로시저③입력 검증(화이트리스트)④최소권한 계정⑤오류메시지 최소화⑥WAF.

인젝션 종류: SQLi(In-band·Blind·Time-based), OS Command Injection, LDAP·XPath·NoSQL Injection.

시험 관점: '동적 SQL=취약(예방책 아님)', ORM 사용 시에도 raw 쿼리 주의.

실무 적용 사례

시큐어 코딩으로 SQL Injection을 예방한다. Prepared Statement(파라미터 바인딩)를 최우선으로, 입력검증·저장프로시저를 보조로 적용한다.

감리사 시험 출제 포인트

정답 해설

동기식 스트림 암호는 평문과 키스트림을 비트 단위 XOR 하므로, 전송 중 한 비트 오류가 발생해도 그 비트에만 영향을 주고 이후 비트로 전파되지 않는다(오류 전파 없음). 따라서 "해당 위치 이후 모든 평문에 오류가 전파된다"는 ④는 틀리다. 오류 전파는 오히려 블록 암호의 CBC 등 연쇄 모드의 특성이다.

①(XOR 생성), ②(낮은 지연·실시간 적합), ③(키/IV 재사용 시 키스트림 재사용 취약)은 모두 옳다.
동기식 스트림 암호는 평문과 키스트림을 비트 단위 XOR하므로 전송 중 한 비트 오류가 그 비트에만 영향을 주고 이후로 전파되지 않는다. 보기 ④는 '해당 위치 이후 모든 평문에 오류 전파'라 했는데 이는 블록 암호 CBC 등 연쇄 모드의 특성이므로 ④가 틀려 정답이다.

오답 분석

보기①②③

XOR 기반 생성, 낮은 지연, 키스트림 재사용 취약성(2-time pad 문제)은 스트림 암호의 올바른 특성이다.

관련 이론 정리
  • 스트림 암호: 동기식은 오류 전파 없음, 자기동기식은 제한적 전파.

  • 키스트림 재사용 금지: 같은 키스트림 재사용 시 XOR로 평문 노출.

  • 시험 포인트: "스트림 암호=오류 전파 없음(블록 CBC와 반대)".

대칭키 암호: 스트림(RC4·ChaCha20, 비트/바이트 단위, 저지연)·블록(DES·3DES·AES, 블록 단위).

블록 운영모드: ECB(취약)·CBC(연쇄·오류 전파)·CTR(스트림화·병렬)·GCM(인증암호 AEAD).

주의: 스트림/CTR은 키·IV(nonce) 재사용 금지(키스트림 재사용→평문 노출).

실무 적용 사례

스트림 암호를 실시간 통신에 적용한다. 비트 오류가 전파되지 않으며, 키/IV 재사용은 금지한다.

감리사 시험 출제 포인트

'스트림 암호=오류 전파 없음(블록 CBC와 반대)'.

  • 위험수용: 잔여위험을 받아들임.

정답 해설

동형암호(Homomorphic Encryption) 는 암호화된 상태 그대로 연산(덧셈·곱셈) 이 가능하여, 데이터를 복호화하지 않고도 처리할 수 있다. 이 때문에 클라우드에서 대용량 민감정보를 안전하게 처리하는 서비스에 오히려 적합하다(다만 연산 비용이 큼). 따라서 "적절하지 못하다"고 한 ②가 가장 적절하지 않은 설명이다.

①(ID기반 암호), ③(프록시 재암호화), ④(속성기반 암호)는 모두 옳은 설명이다.
동형암호는 암호화된 상태 그대로 연산(덧셈·곱셈)이 가능해 데이터를 복호화하지 않고 처리할 수 있어 클라우드에서 대용량 민감정보를 안전하게 처리하는 서비스에 오히려 적합하다(연산 비용은 큼). 따라서 '적절하지 못하다'고 한 ②가 정답이다. ①·③·④는 옳다.

오답 분석

보기①

ID기반 암호는 식별자로 공개키를 만들어 인증서 관리 부담을 줄인다. 옳다.

보기③

프록시 재암호화는 원문 해독 없이 재암호화하여 위임 복호화를 가능케 한다. 클라우드에 유용하다.

보기④

속성기반 암호(ABE)는 속성/정책으로 복호화 가능 여부를 제어한다. 옳다.

관련 이론 정리
  • 동형암호: 부분(PHE)·완전(FHE). 프라이버시 보존 연산.

  • ABE / IBE / PRE: 접근정책·식별자·위임 복호화 기반 암호.

  • 시험 포인트: "동형암호=암호문 연산 가능(클라우드 처리에 적합)".

현대 암호 응용: 동형암호(HE, 암호문 연산·부분/완전 FHE), 프록시 재암호화(PRE, 위임 복호화), 속성기반 암호(ABE, 정책 기반 복호화), ID기반 암호(IBE, 식별자=공개키), 영지식증명(ZKP).

프라이버시 보존 기술: HE·MPC(다자 계산)·차분 프라이버시·연합학습.

시험 관점: '동형암호=암호문 연산 가능(클라우드 적합)'.

실무 적용 사례

고급 암호를 클라우드에 적용한다. 동형암호는 암호문 상태 연산이 가능해 민감정보 처리에 적합하다.

웹 응용 프로그램에 대한 DoS 공격 유형에 대한 설명으로 가장 적절하지 않은 것은?

보기

① 동적 HTTP Reply 공격은 웹 페이지 응답 메시지를 지속적으로 요구하는 공격이다.
② Slow HTTP Header DoS 공격은 HTTP 헤더 정보를 비정상적으로 조작해 서버가 헤더를 완전히 수신할 때까지 연결을 유지하도록 하는 공격이다.
③ Slow HTTP POST 공격은 POST 메소드로 데이터를 매우 느리게 전송해 서버 커넥션을 오래 유지시켜 정상 접속을 받아들일 수 없게 하는 공격이다.
④ HTTP GET Flooding 공격은 GET 메소드를 통해 특정 페이지를 무한대로 요구하는 공격이다.

정답 해설

②(Slow HTTP Header, Slowloris 계열), ③(Slow HTTP POST, R-U-Dead-Yet), ④(GET Flooding)는 모두 실제 웹 DoS 공격 유형에 대한 옳은 설명이다. 반면 ① "동적 HTTP Reply 공격" 은 표준적으로 정의된 DoS 공격 유형이 아니며 설명도 모호·부정확하다. 따라서 가장 적절하지 않은 것은 ①이다.
②(Slow HTTP Header/Slowloris)·③(Slow HTTP POST)·④(GET Flooding)는 실제 웹 DoS 공격 유형에 대한 옳은 설명이다. 반면 ①의 '동적 HTTP Reply 공격'은 표준적으로 정의된 DoS 유형이 아니며 설명도 모호·부정확하므로 가장 적절하지 않은 것은 ①이다.

오답 분석

보기②

Slow HTTP Header(Slowloris)는 헤더를 조금씩 보내 연결을 오래 점유한다. 옳다.

보기③

Slow HTTP POST는 본문을 느리게 전송해 커넥션을 고갈시킨다. 옳다.

보기④

HTTP GET Flooding은 대량 GET 요청으로 서버를 마비시킨다. 옳다.

관련 이론 정리
  • 대역폭 소진형: GET/POST Flooding.

  • 연결 고갈형(Slow): Slowloris(헤더), R-U-Dead-Yet(POST), Slow Read.

  • 시험 포인트: 실제 존재하지 않는/모호한 명칭("동적 HTTP Reply")을 가려낸다.

DoS/DDoS 유형: 대역폭 소진형(UDP/ICMP Flood·GET/POST Flooding·증폭 DNS/NTP), 연결 고갈형(SYN Flood·Slowloris·Slow POST·Slow Read), 애플리케이션 계층(HTTP 요청 폭주).

방어: 레이트 리밋·CDN/스크러빙·SYN 쿠키·연결 타임아웃·WAF·Anycast.

시험 관점: 실재하지 않는/모호한 명칭을 가려낸다.

실무 적용 사례

웹 DoS를 방어한다. Slow HTTP(Header/POST)·GET Flooding 등 실제 공격 유형을 식별하고 대응한다.

정답 해설

이클립스 공격(Eclipse Attack) 은 대상 노드의 피어 연결을 공격자가 통제하는 노드들로만 채워 해당 노드를 네트워크에서 고립(eclipse) 시키고, 블록·트랜잭션 전파 정보를 왜곡해 그 노드의 체인 인식·검증 판단을 조작하는 네트워크 계층 공격이다. 따라서 정답은 ③이다.

  • ①은 51%(과반 해시파워) 공격, ②는 시빌(Sybil) 공격에 대한 설명으로 이클립스와 다르다.
    이클립스 공격은 대상 노드의 피어 연결을 공격자가 통제하는 노드들로만 채워 노드를 네트워크에서 고립시키고 블록·트랜잭션 전파 정보를 왜곡해 체인 인식·검증 판단을 조작하는 네트워크 계층 공격이므로 ③이 정답이다. ①은 51% 공격, ②는 시빌 공격이다.

보기②

보기④

생략(내용 없음).

관련 이론 정리
  • Eclipse: 대상 노드의 아웃바운드/인바운드 연결을 공격자 피어로 독점 → 정보 차단·왜곡.

  • Sybil: 다수 위조 신원. 51%: 합의 장악. (시빌이 이클립스의 선행 수단이 되기도 함)

  • 시험 포인트: "특정 노드 피어 고립=이클립스(네트워크 계층)".

블록체인 공격: 51%(과반 해시파워·이중지불), Sybil(다수 위조 신원), Eclipse(피어 고립·정보 차단), 이중지불, 셀피시 마이닝, 스마트컨트랙트 취약점(재진입 등).

Eclipse↔Sybil: 시빌로 다수 노드를 만들어 이클립스를 실행하기도 한다.

대응: 피어 선택 무작위화·아웃바운드 연결 다양화·고정 피어.

정답 해설

패킷 필터링 방화벽 은 IP 주소·포트·프로토콜 등 패킷 헤더 정보를 기준으로 허용/차단을 결정하며, 데이터 내용(payload)을 깊이 분석하지 않는다. 내용을 심층 분석해 공격을 탐지하는 것은 DPI(심층 패킷 검사)나 애플리케이션 방화벽/IPS 의 기능이다. 따라서 ③이 가장 적절하지 않다.

①(상태 추적), ②(응용계층 제어), ④(경계 접근제어)는 모두 옳다.
패킷 필터링 방화벽은 IP·포트·프로토콜 등 헤더 정보를 기준으로 허용/차단하며 payload를 깊이 분석하지 않는다. 내용을 심층 분석해 공격을 탐지하는 것은 DPI·애플리케이션 방화벽/IPS의 기능이므로, '패킷 필터링이 payload 심층 분석'이라 한 ③이 가장 적절하지 않아 정답이다.

문제

네트워크 보안 기술 및 대표적인 네트워크 공격 유형에 대한 설명 중 가장 적절하지 않은 것은?

보기

① 네트워크 세그멘테이션(Network Segmentation)은 네트워크를 여러 보안 영역으로 논리적·물리적으로 분리하여 공격 확산을 방지하고 보안 정책 적용을 용이하게 하는 보안 기법이다.
② TLS(Transport Layer Security)는 통신 데이터의 기밀성과 무결성 기능 대신에 안전한 네트워크 라우팅 기능을 제공하기 위한 보안 프로토콜이다.
③ DNSSEC(Domain Name System Security Extensions)는 DNS 응답 데이터의 무결성(integrity)과 출처 인증(authentication of origin)을 제공하기 위한 보안 기술이다.
④ Smurf Attack은 네트워크 자원을 소모시켜 정상적인 서비스를 제공하지 못하게 하는 서비스 거부 공격(DoS) 유형에 해당한다.

정답 해설

TLS(Transport Layer Security) 는 통신 데이터의 기밀성·무결성·인증을 제공하는 보안 프로토콜이다. "기밀성·무결성 대신 안전한 라우팅 기능을 제공"한다는 ②는 TLS의 목적을 완전히 잘못 서술했으므로 가장 적절하지 않다(라우팅 보안은 다른 영역). 따라서 정답은 ②이다.

①(세그멘테이션), ③(DNSSEC의 무결성·출처 인증), ④(Smurf Attack=DoS)는 모두 옳다.
TLS는 통신 데이터의 기밀성·무결성·인증을 제공하는 보안 프로토콜이다. 보기 ②는 '기밀성·무결성 대신 안전한 라우팅 기능을 제공'한다고 해 TLS의 목적을 완전히 잘못 서술했으므로 가장 적절하지 않아 정답은 ②이다. ①·③·④는 옳다.

오답 분석

보기①

네트워크 세그멘테이션은 영역 분리로 공격 확산을 억제한다. 옳다.

보기③

DNSSEC는 DNS 응답의 무결성·출처 인증을 제공한다(기밀성은 제공하지 않음). 옳다.

보기④

Smurf Attack은 ICMP 증폭을 이용한 DoS 공격이다. 옳다.

관련 이론 정리
  • TLS: 핸드셰이크로 키 교환, 이후 대칭키로 기밀성·무결성·서버 인증.

  • DNSSEC: 서명으로 무결성·출처 인증(기밀성 X).

  • 시험 포인트: "TLS=기밀성·무결성·인증(라우팅 기능 아님)".

보안 프로토콜: TLS/SSL(전송계층 기밀성·무결성·서버 인증, 핸드셰이크로 키 교환), IPsec(네트워크계층 AH·ESP), SSH(원격 접속), DNSSEC(DNS 무결성·출처 인증, 기밀성은 없음).

네트워크 방어: 세그멘테이션(영역 분리·확산 방지), Zero Trust.

공격: Smurf(ICMP 증폭 DoS)·DNS 스푸핑·MITM. '시험 관점: TLS=기밀성·무결성·인증(라우팅 기능 아님)'.

실무 적용 사례

네트워크 보안 기술·공격을 이해한다. TLS는 기밀성·무결성·인증을 제공하며, DNSSEC는 무결성·출처 인증을, Smurf는 DoS다.

감리사 시험 출제 포인트

'TLS=기밀성·무결성·인증(라우팅 기능 아님)'.
